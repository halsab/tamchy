# Правила работы над «Тамчы»

Инструкции действуют для всего репозитория.

## Источники требований

- [docs/specification.md](docs/specification.md) — каноническое ТЗ v2: целевые режимы, механики, состав ресурсов и критерии готовности. `docs/specification-mvp.md` описывает действующую версию; общие контракты наследуются только по разделу 22 ТЗ v2.
- [docs/content-guide.md](docs/content-guide.md) — состояние подготовки и пути ресурсов; точные реестры — `docs/illustrations-registry.md`, `docs/audio-recording-script.md` и `src/content/v2/`.
- Перед изменением прочитай относящиеся к задаче разделы этих документов. Этот файл — рабочие инструкции, а не замена полного ТЗ. При расхождении продуктовых требований следуй ТЗ; не меняй его молча под удобную реализацию.
- Требования ТЗ обязательны, кроме явно отложенных возможностей. Незавершённые работы V2-01–V2-07 перечислены в разделе 21; не подменяй анализ признаков/силуэтов пустыми проверенными наборами. Не добавляй функции будущего развития без отдельной задачи.
- Проверяй фактическое состояние репозитория по коду и README. Реализованы интерфейс, игровой домен, аудиосервис, подготовка графики и проверки; добавлены все 30 учебных MP3 и 12 подключённых интерактивных реплик. Наличие кода и ресурсов не заменяет проверку критериев приёмки.

## Рабочий подход

- Следуй проверенным паттернам, DRY, KISS и YAGNI. Решения должны быть небольшими, корректными и понятными; не вводи абстракции только ради возможного повторного использования.
- Перед повторным использованием существующего кода проверь его корректность и соответствие ТЗ. Неизбежную совместимость с устаревшим кодом изолируй.
- Сохраняй чужие и несвязанные изменения. Ограничивай diff задачей, избегай стилистической переработки соседнего кода.
- Комментируй кратко и по-русски только неочевидные инварианты, причины решений и сложные алгоритмы.
- Новое поведение разрабатывай через TDD: критерий → падающий по нужной причине тест → минимальная реализация → успешный тест → рефакторинг. Исправление ошибки начинай с воспроизводящего теста.
- Начальная настройка инструментов и подготовка статических иллюстраций допускаются без предварительного падающего теста, но требуют проверки результата по ТЗ.
- Не ослабляй тесты, не удаляй проверки и не обновляй массово эталоны ради зелёного CI. Не выдавай заглушки, наличие файлов или проверку в эмуляции за завершённую приёмку.
- В результате работы указывай, что изменено, какие проверки выполнены и что осталось непроверенным. Для изменений только документации не создавай приложение и не устанавливай зависимости ради запуска будущих команд; проверь согласованность требований и ссылок.

## Продукт и границы v2

- «Тамчы» — полностью татарское статическое PWA без собственного бэкенда, на GitHub Pages. Корневой адрес сразу открывает приложение.
- Три раздела в неизменном порядке: «Төсләр», «Хайваннар», «Саннар». Целевой контент: 13 цветов, 39 животных, числа 1–20; визуальный счёт — 1–10. Точные HEX, татарские названия, словоформы и Clip ID бери из ТЗ и реестров.
- Младший режим (ориентир 2–4 года): услышать → найти, адаптация 2–4 ответов, числа 1–10. Старший (5–7 лет): C1–C4, A1–A3, N1–N3, обычно 4–6 ответов; N2 всегда два. Сложность и число ответов независимы. Пороги младшего режима и компоновка требуют задач V2-03/V2-04.
- Режим выбирает взрослый на экране информации; допускается сохранять только `junior | senior` с ключом префикса `tamchy`. Игровой прогресс, результаты и адаптация остаются в памяти сессии.
- Основные действия доступны нажатием без чтения. На главном экране — три карточки и информация для взрослых; ребёнок не выбирает механику. Домик всегда доступен. Экран взрослых также содержит установку, состояние офлайн, повтор загрузки, версию, обновления, данные и материалы; без пароля, удержания и автоматического показа поверх игры.
- Не добавляй аккаунты, статистику, видимые очки/уровни/серии, достижения, рейтинги, рекламу, покупки, уведомления, музыку, распознавание речи и генерацию учебного контента во время игры. Нет обязательных свайпов, перетаскивания, таймера раунда и итогового экрана.
- Свободное знакомство, голоса животных, чтение, «Әлифба», «Табигать», сказки, диалоги и символическая арифметика вне этой итерации. Не создавай под них пустые экраны или платформы.
- Пока реализован MVP с 4 цветами, 6 животными, числами 1–5, двумя ответами и 42 MP3. Данные `src/content/v2/` и новые мастера подготовлены отдельно; не объявляй их подключёнными. `validate:expansion` проверяет подготовку, действующие `validate:content`/`build` строго проверяют MVP. При миграции переключи строгую проверку на полный набор v2 без разрешения пропусков.

## Стек и архитектура

- React, TypeScript с `strict`, Vite, CSS Modules и общие CSS-переменные. Игра использует `useReducer`, экраны — локальное состояние.
- Локальный JSON-контент проверяется Zod при подготовке/сборке. Аудио — Web Audio API за отдельным адаптером. PWA — `vite-plugin-pwa`, Workbox, `generateSW`.
- Тесты: Vitest, React Testing Library, `user-event`, Playwright. Качество: ESLint, Prettier, проверка типов. CI и публикация — GitHub Actions.
- При настройке выбирай совместимые стабильные версии, фиксируй зависимости в `package-lock.json` и одну поддерживаемую Node.js LTS для локальной среды и CI. Автоматическая установка — `npm ci`.
- Без отдельного обоснования не добавляй Next.js, SSR, Redux, базу данных, серверные функции, тяжёлый маршрутизатор, большой UI-набор, библиотеки анимации и универсальный игровой движок.
- Границы ответственности: контент → чистая игровая логика → экран → браузерные адаптеры. `src/domain/game/` не импортирует React, DOM, аудио, хранилище или сеть. Компоненты отображают состояние и отправляют события; сервисы управляют внешними эффектами.
- Разделы используют общую сессию и проверку ответа; генераторы упражнений различаются по `ExerciseKind`. Не дублируй общую логику и не создавай универсальный игровой движок.
- Переходы реализуй одной чистой функцией. Состояния: подготовка, ожидание ответа, правильный ответ, повторная попытка, переход, пауза, ошибка. Исключай противоречивые сочетания; производные значения не храни второй копией.
- Целевая модель `Exercise` и её `Option`/`Prompt` — discriminated unions по виду. Аудиоподсказка — один Clip ID либо последовательность. Отдельные каталоги цветов, животных, чисел, форм, размеров, считаемых объектов, клипов, проверенных traits и конфликтов силуэтов. Нынешний `LearningItem` с одиночными `labelAudio`/`promptAudio` относится к MVP; не расширяй его множеством необязательных полей.
- Упражнение содержит ID, раздел, вид, сложность, подсказку, варианты и `correctOptionId`. Ответ проверяется по ID, а не позиции или подписи. Текущий MVP хранит `roundId/categoryId/targetId/optionIds`; миграция сохраняет отсечение устаревших операций. Сессия, результаты и раунды не сохраняются в `localStorage` или IndexedDB.
- Размещай код по структуре раздела 9.2 базового ТЗ MVP, сохранённой разделом 22 ТЗ v2: `src/app`, `domain/game`, `content`, `features/{home,game,parents}`, `services/{audio,assets,pwa}`, `shared/ui`, `styles`; подготовку и проверки — в `scripts`, интеграционные и сквозные тесты — в `tests`. Создавай каталоги по мере реализации.

## Инварианты игры и восстановления

- В прямом распознавании каждый элемент становится целью один раз за перемешанный цикл; на стыке циклов цель не повторяется подряд. Помеха — другой элемент того же раздела. Правильный вариант единственный; позиция перемешивается независимо, без постоянного места и строгого чередования.
- Источник случайности, часы и внешние сервисы передавай как зависимости. Не вызывай случайность при рендере и в функции переходов. В тестах используй детерминированные значения.
- До приёма ответов подготовь все обязательные изображения и клипы текущего упражнения. Ответ разрешается после фактического начала задания; дослушивание не обязательно.
- Правильный ответ отменяет задание, выделяет выбранную карточку, показывает небольшой знак подтверждения и воспроизводит название/число. До следующего раунда должны пройти и 1200 мс после ответа, и 300 мс после окончания учебного названия, следующего за предусмотренной похвалой. Во время реакции ответы и повтор заблокированы. Визуальное подтверждение C3 без учебной речи обрабатывается по разделу 13.5 ТЗ v2.
- Неправильный ответ даёт мягкую реакцию на 250 мс, затем предусмотренная реплика и исходное задание по разделу 13.5 ТЗ v2. Цель и расположение не меняются. После двух ошибок правильная карточка получает статичную обводку до ответа; автоматического ответа нет.
- Повтор прерывает текущую запись и запускает задание сначала, без очереди. Бездействие вызывает один повтор за раунд через 10 секунд после окончания задания; любое действие отменяет текущий таймер бездействия.
- Принимай только первое допустимое нажатие. Не учитывай отдельно касание и порождённый им клик. Недопустимые события и результаты устаревших запросов, таймеров и аудио игнорируются по ID сессии и раунда.
- Домик всегда доступен, включая загрузку, ошибку и переход. Выход отменяет звук, запросы и таймеры сессии. Смена ориентации не меняет раунд и расположение вариантов.
- При скрытии страницы и блокировке останавливай звук и таймеры. Возврат показывает крупную кнопку продолжения без автозвука. До ответа продолжается тот же раунд с повтором задания; после принятого правильного ответа выполняется ровно один переход без повторного зачёта.
- Ошибка хранит ресурс и фазу для восстановления. Без обязательной картинки или аудио ответы не принимаются; доступны повтор и домик. Ошибка подтверждения не отменяет уже принятый ответ. Ошибка необязательного декора не останавливает игру.
- Тайм-аут загрузки обязательного ресурса — 15 секунд. Повтор загрузки — явным действием пользователя, без бесконечных запросов. Стек и технические сообщения не попадают в детский интерфейс.

## Аудио

- Один сервис владеет одним `AudioContext`; одновременно играет не более одной записи. MP3 загружается целиком через `fetch`, декодируется `decodeAudioData` и воспроизводится из буфера.
- Создание/возобновление контекста запускается непосредственно из обработчика нажатия до ожидания сети; результат проверяется. Обычный вход в раздел активирует звук первым касанием без дополнительного экрана «Начать».
- Запрет воспроизведения, прямой вход и перезагрузка обрабатываются крупной кнопкой активации звука. Не считай однажды полученное разрешение постоянным.
- Повтор, ответ, переход и выход отменяют прежнюю запись и обработчики завершения. Отмена не является успешным окончанием записи. Системное прерывание обрабатывается как пауза; зависшая операция не блокирует навигацию и восстановление.
- Держи ограниченный кэш декодированных буферов с вытеснением, ориентир — 8 МиБ; готовь текущие и ближайшие записи, не декодируй всю библиотеку. Не обещай обход громкости или беззвучного режима ОС.

## Язык, изображения и ресурсы

- Весь собственный интерфейс, ошибки, задания, экран для взрослых и доступные названия — на татарском; HTML имеет `lang="tt"`, направление слева направо. Русский допустим в документации разработчика.
- Строки интерфейса централизованы в `tt.json`; не дублируй их в компонентах. В контенте хранятся полные названия и задания. Не добавляй переключатель языка, библиотеку многоязычности, русский запасной текст или необработанные сообщения библиотек.
- Следуй реестру `docs/content-guide.md`. Мастер-PNG в `assets-source/` нельзя пережимать, уменьшать, переименовывать, перемещать или перезаписывать при подготовке производных. Не импортируй их в приложение, не копируй в `public`, `dist` или офлайн-кэш.
- Подготовка текущего MVP автоматически создаёт 10 WebP и четыре иконки до проверки/сборки. Целевой набор v2: 43 WebP, 9 локальных SVG и четыре PNG-иконки; генерация и подключение отслеживаются V2-07. Сохраняй прозрачность, пропорции, пути и исходные байты. Хеши всех 53 мастеров закреплены в `src/content/v2/graphics.json`.
- Из `assets-source/icons/app-icon-master.png` создавай `public/icons/pwa-192x192.png`, `pwa-512x512.png`, отдельный `pwa-maskable-512x512.png` и `apple-touch-icon.png` 180×180. Для maskable соблюдай безопасную область; фон иконки непрозрачный. Значки управления — локальные SVG.
- В данных используй пути `assets/images/…`, `assets/audio/tt/…`, `icons/…`, разрешаемые относительно Vite `base`. Запрещены ведущий `/`, внешние URL, `..` и префиксы `public/`, `dist/`, `assets-source/`.
- Цветовые фишки C1/C2 — одинаковые SVG/CSS-элементы, различающиеся только точным учебным цветом. C2 использует утверждённые предметы/формы, C3 — цвет/форму/размер. SVG окрашиваются через `currentColor`; при повторном inline-подключении ID масок и градиентов уникальны. Животные — целиком, без фона и посторонних предметов, сопоставимого масштаба.
- В числах цифра — текст, визуальные группы 1–10 формируются кодом из одного типа объекта внутри задания. Пул — яблоко, шесть форм и три SVG-предмета. Числа 11–20 используются для распознавания цифры по озвучке. Не используй готовые группы, перекрытия и размер предмета как подсказку. В N3 сумма ≤10, разность положительна, ноль пока не используется.
- Аудиоконструктор v2 — 175 клипов из пяти WAV-мастеров, записанных владельцем одним голосом. Фразы собираются из целых слов/словоформ, без отделения суффиксов; последовательность отменяется целиком. До массовой записи проверяются склейки. Синтез речи не используется. Старые цельные задания остаются только для действующего MVP.
- Все 12 существующих интерактивных реплик сохраняются и используются в обоих режимах по разделу 13.5 ТЗ. Они не подменяют учебные клипы. Базовый набор v2 — 187 (175 + 12); дополнительные тексты пока не утверждены, задача V2-05. Ошибка реплики не отменяет учебную запись, предел ожидания — 2 секунды.
- Не создавай пустые MP3, сгенерированный голос, звуковые заглушки или копии одной записи под разными именами. Предоставленные MP3 сохраняй без ненужного перекодирования. Необработанные исходные записи при их появлении храни в `assets-source/audio/tt/` вне `public/`, `dist` и офлайн-кэша. `.gitkeep` нужен только пустым каталогам и не является ресурсом сборки.
- До миграции строгие `validate:content` и `build` требуют все 42 MP3 текущего MVP. Релиз v2 потребует всех 187 клипов и проверенных производных. Ожидаемые записи отмечаются только в подготовке; не ослабляй релизные проверки и не выдавай наличие реестра за готовое аудио.
- Публикуемые MP3 — моно, ориентир 64–96 кбит/с; мастер-записи вне сборки. Финальные тексты, произношение, соответствие картинок и звук на телефоне проверяет владелец. Не объявляй эту проверку выполненной без подтверждения.
- Контент-проверка должна отклонять дубли ID, неверные типы/цвета/числа, неизвестные категории, недостающие строки и ресурсы, неполную озвучку и мастер-файлы в сборке. Проверяй регистр путей на Linux и соответствие обязательных ресурсов precache. Сгенерированные манифесты не редактируй вручную.

## Интерфейс

- Стиль — спокойные «игрушечные карточки», крупные иллюстрации, округлые формы, свободное пространство. Без глянцевого объёма, перегруженной сцены и постоянной анимации. Орнамент допустим только как малозаметный декор вне обучения и управления.
- Сохраняй токены раздела 5.1 базового ТЗ: фон `#FFF9F2`, поверхность `#FFFFFF`, текст/значки `#27332F`, акценты `#E3F0E6`, `#FBE6D9`, `#E1EDF7`. 13 точных учебных HEX находятся в `src/content/v2/colors.json` и разделе 7.1 ТЗ v2. Шаг отступов 8 px, скругления карточек 24–32 px; белый `#FFFFFF` не изменять ради контраста.
- Минимумы в CSS-пикселях: служебная кнопка 56×56, ответ 128×128, промежуток ответов 16, высота карточки раздела на компактном телефоне 112. Не уменьшай их ради размещения.
- Проверяй окна 320×568, 390×844, 768×1024, 1024×768 и 844×390. Главный и игровой экраны при обычном масштабе не прокручиваются; при увеличении текста допустима вертикальная прокрутка вместо обрезания. Учитывай safe area и `dvh` с резервным вариантом; не блокируй ориентацию и масштабирование.
- Используй системный шрифт с татарскими символами `Ә ә Ө ө Ү ү Җ җ Ң ң Һ һ`. Подписи — от 20 px, названия разделов — от 24 px, служебный текст для взрослых — от 16 px. Текст не запекается в изображения.
- Используй настоящие кнопки с татарскими доступными названиями, видимым фокусом и поддержкой Tab, Enter, Space. Декор не дублирует озвучивание. Контраст текста — от 4,5:1, необходимой графики управления и состояний — от 3:1; подтверждение не только цветом.
- Реакция на нажатие — 100–160 мс, игровая анимация — не более 400 мс. При `prefers-reduced-motion` убирай масштабирование и перемещения, оставляя статичную обратную связь.

## Навигация, PWA и публикация

- Маршруты: `#/`, `#/colors`, `#/animals`, `#/numbers`, `#/parents`. Неизвестный маршрут заменяется главным; обновление раздела начинает новую сессию. Браузерный «Назад» перемещает между экранами; раунды не попадают в историю. Домик работает и при прямом входе.
- Манифест: стабильный `id`, `name` и `short_name` «Тамчы», `lang: tt`, `display: standalone`, согласованные `start_url`, `scope`, цвета и иконки, без фиксации ориентации. Запуск установленного приложения ведёт на главный экран.
- После оболочки автоматически готовь полный набор текущей версии, сохраняя онлайн-игру и приоритет текущих ресурсов. MVP включает 42 MP3; v2 — 187, 43 WebP, 9 SVG, иконки, HTML, JS, CSS и словари. MP3/WebP/SVG должны входить в precache явно; подготовленные исходники не доказывают готовность офлайн.
- Статус «готово» допустим только после успешной установки service worker и подтверждения полного набора текущей версии. Флаг `localStorage`, наличие файлов в `public`, установка PWA и `navigator.onLine` сами по себе этого не доказывают. Не выдумывай процент загрузки.
- При недоступности service worker/хранилища сохраняй онлайн-игру без обещания офлайн. При неполном наборе показывай честную ошибку с повтором; после очистки данных потребуется подготовка заново.
- Обновляй код и контент согласованной версией с ревизиями/хешами. Используй `registerType: 'prompt'`; не вызывай `skipWaiting` и не перезагружай текущую игру. Обновление активируется естественно после закрытия всех окон старой версии; объяснение находится на экране для взрослых.
- Сбой установки новой версии сохраняет рабочую старую. Старые ресурсы удаляются только после успешной активации; проверяй несколько вкладок.
- Публикуй только проверенный `dist` через GitHub Actions по HTTPS. Для проектного Pages используй конфигурируемый `base: '/<repo>/'`; согласуй с ним все ресурсы, манифест и service worker. Не рассчитывай на серверные перенаправления или произвольные заголовки.
- Ограничивай scope каталогом приложения, имена кэшей и возможные будущие ключи хранения — префиксом `tamchy`. Запрещено удалять все кэши домена или снимать регистрацию всех service worker: рядом могут работать другие приложения.
- Успешный push в `main` автоматически публикует проверенный артефакт. Отдельный ручной «Деплой без тестов» повторно использует готовый артефакт успешных проверок `main`, сверяя целостность и исходный коммит, без повторных тестов, Lighthouse, браузеров и сборки.
- Публикация — только после проверок и из того же артефакта, который тестировался. Сторонние ветки не получают права публикации; права Pages минимальны, версии/ревизии официальных GitHub Actions зафиксированы. Исключай одновременные публикации; проверяй реальный URL и описывай откат.

## Конфиденциальность и бюджеты

- Не собирай личные данные, ответы и историю использования ребёнка. Не добавляй аналитику, удалённые журналы ошибок, сторонние скрипты, внешние шрифты или запросы разрешений на камеру, микрофон, уведомления и геолокацию.
- Сеть во время работы используется только для собственных статических ресурсов и технического обновления. Все публикуемые материалы публичны: никаких секретов, API-ключей и личных данных в коде и сборке.
- Не вставляй произвольный HTML; проверяй SVG на скрипты и внешние ссылки, зависимости — на известные уязвимости. Веди происхождение и условия использования материалов. Не обещай полную анонимность: собственная аналитика отсутствует, но Pages имеет техническое журналирование по ТЗ.
- Бюджеты сборки: начальный JS ≤150 КиБ gzip без service worker, CSS ≤20 КиБ gzip, ресурсы первого экрана ≤750 КиБ передаваемых данных, полный обязательный набор ≤8 МиБ, отдельная публикуемая иллюстрация ≤150 КиБ. Лимит иллюстрации не относится к мастер-PNG. Для расширенного набора v2 полный размер требуется повторно измерить и подтвердить; новый лимит не выдумывать (V2-07).
- Производительность: реакция на касание p95 ≤100 мс на контрольном устройстве, CLS ≤0,1, LCP ≤2,5 с. Для Lighthouse фиксируй версию и мобильный профиль, используй медиану трёх прогонов релизной сборки. Размеры проверяй автоматически; отзывчивость и звук — также на устройстве.

## Проверки и готовность

- Сохраняются T01–T18 и A01–A12 базового ТЗ с расширением по разделу 22 ТЗ v2, а также проверки новых механик из разделов 17 и 19. Для `domain/game` покрытие строк и ветвей не ниже 90%; процент не заменяет сценарии гонок, отмены, паузы и восстановления.
- Компонентные тесты проверяют действия и видимый результат, а не внутренности React или CSS-классы. В модульных тестах подменяй время; в сквозных жди наблюдаемое состояние вместо произвольных задержек. Нестабильность исправляй, не скрывай повторами.
- Сквозные проверки выполняй против итоговой сборки с настоящим service worker: Chromium и WebKit в мобильных размерах, основные настольные сценарии также в Firefox. Тест настоящего офлайн не должен подменять кэш и сеть моками; проверяй все задания и записи после отключения сети, повторного запуска и обновления страницы.
- До проверки контента и сборки должен отработать этап подготовки производных. При настройке проекта обеспечь этот порядок автоматически; отдельное имя команды подготовки в ТЗ не задано.
- Команды для подготовки нового выпуска — контракт раздела 17 базового ТЗ, сохранённый разделом 22 ТЗ v2. Повторный деплой готового проверенного артефакта не запускает их заново; при изменении только CI/документации проверяй затронутые скрипты, workflow и ссылки без повторной приёмки неизменённого приложения:

  ```text
  npm ci
  npm run format:check
  npm run lint
  npm run typecheck
  npm run validate:content
  npm run test:unit -- --coverage
  npm run test:integration
  npm run build
  npm run check:assets
  npm run check:budgets
  npm run test:e2e
  ```

- Добавь `npm run dev` и `npm run preview`; `preview` служит проверке собранной версии. Браузеры Playwright устанавливаются при подготовке CI. Не заявляй выполнение команды до появления и успешного запуска её реализации.
- Поддержка: Safari iOS/iPadOS 17+ с проверкой минимальной и актуальной стабильной версий; две последние стабильные версии Chrome на Android и Chrome, Safari, Firefox на компьютере. Фиксируй фактически проверенные версии ОС и браузеров.
- Playwright WebKit не заменяет Safari на реальном iPhone; подменённый звук не доказывает воспроизведение. Для приёмки нужны реальный iPhone и Android, установка/повторный запуск, звук, касания и авиарежим в том же контексте, где подготовлены ресурсы; дополнительно — планшетная компоновка.
- После утверждения материалов закрепи визуальные эталоны главного экрана и трёх игр на телефоне и планшете; изменения эталонов проверяются вручную.
- Временные материалы допустимы при разработке, но не в финальном MVP. Приёмку владельцем и наблюдение за 2–3 детьми с согласия взрослых нельзя подменять автоматическими проверками. Без наблюдения A02 остаётся непроверенным.
- При реализации поддерживай документацию архитектуры, запуска, добавления контента, проверки аудио/офлайн/обновлений, происхождения материалов и релиза по текущему ТЗ и статусу реализации. В протоколе различай «выполнено», «не выполнено» и «не проверено».
