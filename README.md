В `src/content/v2/` зарегистрированы 13 цветов с точными HEX, 56 PNG-мастеров и 189 аудиоклипов (177 ожидаемых + 12 существующих реплик). Подробности и пути — в [руководстве по контенту](docs/content-guide.md), тексты — в [сценарии записи](docs/audio-recording-script.md).

`npm run validate:expansion` проверяет подготовленные данные и мастера. Она не подтверждает готовность релиза v2. Действующая игра и её строгая сборка используют прежний каталог и 42 MP3. ## Работающая версия MVP

Реализованы шесть этапов татарского приложения для детей: среда и каталог, чистый игровой домен, браузерные адаптеры, настоящий интерфейс, PWA и подготовка выпуска. Главное меню, три игровых раздела и информация для взрослых связаны hash-навигацией и одним владельцем `useGameSession`. При наличии корректных ресурсов игра проводит раунды; отсутствие обязательного изображения или записи показывает восстановление с повтором и домиком.

Добавлены все 30 учебных MP3: задания и подтверждения работают через настоящий Web Audio. Все 12 интерактивных реплик подключены к игровым действиям и входят в сборку и офлайн-набор. Браузерные проверки используют реальные записи. Реализованы установка, полный офлайн и безопасные обновления. Настроены автоматический деплой успешного push в main и отдельный workflow «Деплой без тестов» для готового артефакта. Первый релиз выполнен владельцем; новые изменения требуют отдельной публикации. Приёмка на устройствах остаётся отдельным действием.

Требования: [ТЗ](docs/specification.md). Материалы и тексты записей: [руководство по контенту](docs/content-guide.md).

Границы домена, владение ресурсами и контракт адаптеров: [архитектура](docs/architecture.md). Покрытые сценарии и ограничения доказательств: [проверки](docs/testing.md). Настройка Pages, запуск, отчёты, откат и таблица A01–A12: [первый выпуск](docs/release.md).

## Установка и запуск

Нужны **Node.js 24.20.0 LTS** и поставляемый с ним **npm 11.19.0**. Версия Node закреплена в `.nvmrc`, CI читает этот же файл. `.npmrc` отклоняет несовместимую среду. При использовании nvm:

```sh
nvm install
nvm use
npm ci
npm run dev
```

Можно установить ту же версию Node другим менеджером; проверяйте `node --version` и `npm --version`. Не используйте системный Node другой версии. `dev` готовит изображения и открывает сервер на `http://127.0.0.1:5173`; наличие MP3 для запуска не требуется.

## Структура и границы

```text
src/app/                 StrictMode, владелец сессии, экраны и hash-навигация
src/content/             catalog.json, tt.json, discriminated union LearningItem
src/domain/game/         модели, генератор, чистые переходы, требования к адаптерам и тесты
src/features/{home,game,parents}/  экраны; game также содержит useGameSession и исполнитель
src/shared/ui/           домик, локальные SVG и стили кнопок
src/services/assets/     URL, отменяемая подготовка и кэш декодированных изображений
src/services/audio/      ленивый AudioContext, единственная запись, PCM-кэш с LRU
src/services/pwa/        регистрация, проверка Cache Storage, восстановление и установка
src/styles/              общие стили и токены из ТЗ
scripts/lib/             Zod, файловые проверки, список ресурсов, плагин сборки
scripts/                 подготовка изображений и команды проверки контента
tests/integration/       проверки сборки, сессии и навигации настоящего App
tests/e2e/               браузерные проверки релизного артефакта, офлайна и обновлений
tests/helpers/           управляемые браузерные границы только для тестов
assets-source/           неизменяемые мастер-PNG
public/assets/images/    производные WebP, создаются автоматически
public/icons/            производные иконки, создаются автоматически
public/assets/audio/tt/  30 учебных MP3 и 12 интерактивных реплик
```

Node-скрипты запускаются встроенной поддержкой TypeScript в зафиксированной Node LTS. Конфигурации TypeScript разделены; инструменты подготовки не импортируются клиентским кодом. Домен отдельно проверяется без DOM, Node и Vite-глобалов; его импорты и обращения к внешним эффектам ограничены ESLint. Zod и sharp находятся в devDependencies. ESLint запрещает браузерному коду импортировать Node, скрипты, мастер-ресурсы и инструменты сборки; плагин дополнительно проверяет модули итогового bundle.

Каталог содержит разделы в порядке `colors`, `animals`, `numbers` и точный набор 4/6/5 элементов. Схема проверяет уникальность ID, вид элемента, принадлежность разделу, обязательные поля, цвета, значения чисел, назначение и имена ресурсов. Тест сверяет названия и полные задания с приложением A. Все исходные строки интерфейса из приложения A перенесены в `tt.json`; интерфейс и HTML-title используют этот словарь.

Проверка существования обходит каждый сегмент пути с точным регистром, отклоняет пустые файлы, каталоги и симлинки. Playwright дополнительно сверяет содержимое всех 42 MP3 в `dist` с файлами в `public`, декодирует их и проверяет моно. Локально проверены формат и полное декодирование всех 42 записей. Произношение и качество звучания на телефоне требуют отдельной приёмки владельцем.

## Использование игровой сессии

`App` один раз вызывает `useGameSession()` над всеми экранами и напрямую связывает нажатие раздела с `game.start(category)`. Этот обработчик синхронно создаёт/возобновляет аудиоконтекст, создаёт новый `sessionId` и первый раунд вне рендера. Возвращаемые действия: `answer(id)`, `repeat()`, `retry()`, `continueGame()`, `exit()` и отдельное `activity()`. Для одного нажатия используется один `onClick`; не добавляйте независимый зачёт `touchend`.

Хук отправляет `ACTIVITY` перед ответом, повтором и продолжением. `exit()` немедленно отменяет операции и освобождает генератор; кэши адаптеров живут до unmount и могут пригодиться при следующем входе. `visibilitychange` и системное прерывание переводят сессию в паузу с немедленной остановкой. Возвращение не запускает звук; `continueGame()` снова активирует контекст из пользовательского обработчика. После ошибки `retry()` явно повторяет подготовку и проверяет разрешение звука. Состояние `error` содержит только доменную причину и ресурс.

Один экземпляр хука владеет одним аудиосервисом, сервисом изображений и текущим исполнителем. Независимые ресурсы раунда загружаются параллельно, готовность требует декодирования; весь каталог не загружается. Ограничение аудиокэша — 8 МиБ PCM, активный source удерживает свой буфер до остановки. Нет ни звуковых заглушек, ни синтеза речи. Подробности жизненного цикла и тестовых зависимостей — в [архитектуре](docs/architecture.md).

## Экраны и браузерная проверка

Маршруты: `#/`, `#/colors`, `#/animals`, `#/numbers`, `#/parents`. Неизвестный hash заменяется главным через `replaceState`; «Назад» и «Вперёд» работают между экранами. Раунды не добавляют записей в историю. Домик всегда открывает главный экран и останавливает сессию.

Нажатие раздела активирует аудио непосредственно в обработчике. Прямой адрес, перезагрузка и возврат в раздел через историю создают новую сессию с кнопкой «Тыңла». Повторное событие hash не перезапускает уже открытую сессию. Экран для взрослых показывает номер из `package.json` и идентификатор выпуска, сведения о данных и материалах, инструкции установки и реальные состояния офлайна и обновления. Повтор загрузки доступен при ошибке; системное приглашение установки — только при наличии API и по нажатию.

```sh
npx playwright install chromium webkit firefox
npm run test:e2e
```

Команда сама последовательно выполняет строгий `build`, `check:assets`, `check:budgets` и браузерные тесты только для `/tamchy/` в `dist`, используя `preview` на `127.0.0.1:4173`. Хеши фиксируются до тестов и сверяются после; проверенная копия сохраняется в `.release/subpath/dist`, отчёт — рядом с ней, вне сайта. Другой preview на этом порту должен быть остановлен. Можно передать фильтр: `npm run test:e2e -- --project=chromium`; такой прогон помечается `filtered` и не подходит для Lighthouse/публикации. Не запускайте одновременно несколько сборок в `dist`.

Проверки охватывают пять размеров окна, клавиатуру, увеличение текста до 200% и reduced motion. Скриншоты главного экрана, трёх разделов и информации для взрослых в размерах 390×844 и 768×1024 сохраняются в системном временном каталоге `tamchy-screenshots/`; путь можно задать переменной `TAMCHY_SCREENSHOTS`. Диагностика Playwright находится в системном временном каталоге `tamchy-e2e/`, либо в `TAMCHY_E2E_REPORTS`; CI сохраняет её в `reports/e2e/`. Это материалы проверки, а не утверждённые визуальные эталоны. В обычных сценариях любой отказ ресурса проваливает тест. Только отдельные негативные сценарии используют изолированный HTTP-сервер, который прерывает соединение или возвращает HTTP 503. Это действует также на запросы service worker; глобального отключения PWA и подмены Cache Storage нет. Дополнительно проверяются полные циклы всех трёх разделов с настоящими заданиями, ошибками, подсказкой, повтором и подтверждениями.

## PWA и полный офлайн

После загрузки оболочки приложение регистрирует `sw.js` в пределах `VITE_BASE`. `vite-plugin-pwa` 1.3.0 и Workbox 7.4.1 используют `generateSW` и `registerType: 'prompt'`; остальные версии зависимостей сохранены. Dev и технический `build:check` не регистрируют worker и не обещают офлайн.

Список precache получается из проверенного каталога и итогового dist: HTML, клиентский JS со встроенными каталогом, словарём и SVG, CSS, манифест, 10 WebP, 4 иконки и 42 MP3. `copyPublicDir: false` сохранён. Мастер-файлы и `.gitkeep` не копируются. Workbox скачивает файлы последовательно, с низким приоритетом и ограничением времени запроса; игра использует свои обычные запросы.

«Интернетсыз уйнарга була» появляется только после активации worker и сверки всех сохранённых ответов с SHA-256 соответствующего выпуска. Проверка читает точные ключи Cache Storage, не вызывает fetch и не ремонтирует набор. Она выполняется при запуске, открытии экрана взрослых, возвращении страницы и смене контроллера. После очистки или частичной потери данных готовность снимается; кнопка повтора явно восстанавливает ресурсы с проверкой их содержимого. При отказе API остаётся онлайн-игра.

Обновление готовится отдельно от состояния работающей версии. Изменение MP3 учитывается независимо от номера пакета; ревизии защищают A от ресурсов B. Новая версия ожидает закрытия **всех** окон и вкладок приложения. Принудительной активации и перезагрузки игры нет. Сбой B сохраняет A; старые ключи удаляет Workbox только при успешной активации. Префикс кэша содержит `tamchy` и хеш base, суффикс — полный scope. Чужие кэши и регистрации не удаляются.

Для проверки релизного PWA:

```sh
npm run build
npm run check:assets
npm run check:budgets
npm run preview -- --port 4173 --strictPort
```

Для подкаталога задайте `VITE_BASE=/tamchy/` во всех четырёх командах. `test:e2e` сам задаёт и проверяет только `/tamchy/`; не запускайте параллельно другую сборку в общий dist.

Бюджеты: JS и CSS — gzip всех клиентских файлов соответствующего типа (консервативно, включая возможные дополнительные чанки, без worker); первый экран — эти файлы, HTML и манифест в gzip плюс три иллюстрации меню и все иконки в исходном размере. Полный набор — все файлы dist, включая служебные PWA-файлы. Лимит отдельной иллюстрации проверяется для каждого WebP/PNG/SVG. Это автоматические оценки передаваемых байтов, а не сетевой замер конкретного хостинга. LCP, CLS и отзывчивость требуют отдельных измерений.

Архитектурные детали, границы доказательств и **невыполненный** ручной протокол установки, авиарежима, звука и обновлений на iPhone/Android приведены в [архитектуре](docs/architecture.md) и [протоколе проверок](docs/testing.md). Механизм публикации описан в [release.md](docs/release.md); сама публикация и окончательная приёмка MVP пока не выполнены.

## Графика

`assets:prepare` читает перечень изображений из проверенного каталога. Десять иллюстраций уменьшаются целиком с 1254×1254 до 768×768, без обрезания, затем кодируются sharp в WebP: quality 84, alphaQuality 100, effort 6. Каждая производная проверяется на формат, размеры, фактическую прозрачность и лимит 150 КиБ. Исходники не перезаписываются; SHA-256 всех 11 PNG сравниваются до и после обработки, в том числе при ошибке подготовки.

Обычные PNG-иконки имеют размеры 192, 512 и 180 пикселей. Производные используют палитру до 256 цветов с дизерингом и также проверяются на лимит 150 КиБ. У maskable отдельная композиция: исходное изображение целиком помещено в центр непрозрачного холста 512×512 в квадрат 288×288. Его диагональ меньше диаметра безопасного круга 80%, поэтому системная маска не обрежет значимые части.

Выходные файлы записываются атомарно только по известным путям. `public` и соседние материалы не очищаются. Повторная подготовка при зафиксированных зависимостях проверена сравнением хешей производных. Производные исключены из Git и воспроизводятся локально и в CI; мастер-PNG остаются в Git.

Vite не копирует весь `public`: плагин переносит только проверенные изображения, иконки и обязательные учебные и интерактивные MP3. `.gitkeep`, `.DS_Store`, мастер-файлы, пользовательские посторонние материалы не попадают в артефакты.

## Добавление озвучки MVP

Этот раздел описывает прежние файлы. Для новых 177 клипов используйте [сценарий v2](docs/audio-recording-script.md).

1. Вычитать тексты и записать все 30 названий и полных заданий одним голосом по [реестру MVP](docs/content-guide-mvp.md). Фразы записываются целиком.
2. При появлении исходных записей создать `assets-source/audio/tt/` и хранить оригиналы там, вне сборки.
3. Подготовить финальные моно MP3, ориентир 64–96 кбит/с; поместить в `public/assets/audio/tt/{colors,animals,numbers}/` с точными именами `*-label.mp3` и `*-prompt.mp3`. `.gitkeep` можно удалить только из заполненных каталогов.
4. Выполнить `npm run validate:content`. Пустые файлы и неполный набор не проходят проверку. Не создавать заглушки или копии одной записи.
5. До релиза добавить проверки формата/декодирования, получить проверку владельцем текстов, произношения, соответствия записей и звучания на телефоне; зафиксировать происхождение и условия использования материалов.

Все 12 реплик из `interaction/` подключены отдельно от учебных элементов, проверяются при сборке и включены в офлайн. Последовательности и частота использования описаны в [ТЗ, раздел 4.1.1](docs/specification-mvp.md#411-интерактивные-реплики).

## CI и проверенный объём

Пятый этап: локально прошли 216 модульных/компонентных, 16 интеграционных и 96 браузерных сценариев для двух баз. Полный офлайн, восстановление, A→B, сбой B и изоляция проверены во всех трёх движках; размеры укладываются в бюджеты. Точные результаты и ограничения — в [протоколе](docs/testing.md#результат-пятого-этапа).

Workflow `Проверки проекта` выполняет проверки push и pull request. Успешный push или ручная полная проверка из `main` автоматически запускает отдельный `Деплой без тестов`. Для публикации уже проверенного выпуска открыть **Actions → Деплой без тестов → Run workflow → main**: пустое `run_id` выбирает последний успешный запуск проверок, заполненное — конкретный запуск. Этот workflow не запускает сборку, тесты, Lighthouse или браузеры; он переиспользует исходный tar, сверяет целостность/коммит и публикует Pages. Обе формы публикации используют одну очередь; PR и сторонние ветки не публикуются. [Подробности и откат](docs/release.md#автоматическая-и-ручная-публикация).

После полного `test:e2e` команды `check:published:local` и `check:lighthouse` читают сохранённую копию `/tamchy/` без пересборки. Lighthouse 13.4.1 использует три свежих профиля Chromium для неё; пороги — медиана LCP ≤2,5 с и CLS ≤0,1. Исходные отчёты, окружение и ошибки сохраняются в `reports/`; CI загружает диагностику и при неуспехе. Артефакт Pages и отчёт с версией/коммитом/SHA-256 хранятся отдельно. Подробности — в [инструкции выпуска](docs/release.md).

Это не полная приёмка MVP. T01–T18 и пороги покрытия сохранены. Требуют подтверждения реальные iPhone/Android, установка, авиарежим, воспринимаемое качество звука, p95 касаний, языковая приёмка, происхождение и условия материалов, визуальные эталоны и наблюдение с детьми. Фактическая публикация Pages также не проверена. Статусы A01–A12 приведены в [протоколе выпуска](docs/release.md#приёмка-первого-выпуска).

В Chromium 146 через Playwright проверены dev и технические артефакты для обеих баз, перезагрузка, декодирование всех 14 графических ресурсов и отсутствие ошибок консоли; минимальный экран помещается в пять размеров окна из ТЗ.
