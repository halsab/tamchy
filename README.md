# Тамчы

Реализованы четыре этапа татарского приложения для детей: среда и каталог, чистый игровой домен, браузерные адаптеры и настоящий интерфейс. Главное меню, три игровых раздела и информация для взрослых связаны hash-навигацией и одним владельцем `useGameSession`. При наличии корректных ресурсов игра проводит раунды; отсутствие обязательного изображения или записи показывает восстановление с повтором и домиком.

Добавлены все 30 учебных MP3: задания и подтверждения работают через настоящий Web Audio. Ещё 12 реплик сохранены для будущего расширения и не входят в сборку. Браузерные проверки используют реальные записи; PWA, service worker, офлайн, обновления и публикация ещё не реализованы.

Требования: [ТЗ](docs/specification.md). Материалы и тексты записей: [руководство по контенту](docs/content-guide.md).

Границы домена, владение ресурсами и контракт адаптеров: [архитектура](docs/architecture.md). Покрытые сценарии и ограничения доказательств: [проверки](docs/testing.md).

## Установка и запуск

Нужны **Node.js 24.20.0 LTS** и поставляемый с ним **npm 11.19.0**. Версия Node закреплена в `.nvmrc`, CI читает этот же файл. `.npmrc` отклоняет несовместимую среду. При использовании nvm:

```sh
nvm install
nvm use
npm ci
npm run dev
```

Можно установить ту же версию Node другим менеджером; проверяйте `node --version` и `npm --version`. Не используйте системный Node другой версии. `dev` готовит изображения и открывает сервер на `http://127.0.0.1:5173`; наличие MP3 для запуска не требуется.

| `npm run build`                           | Типы, графика, строгая проверка контента, затем релизный `dist`                                      |
| `npm run preview`                         | Просмотр только существующего `dist`                                                                 |

**Все 30 обязательных учебных MP3 добавлены.** `validate:content` и `build` проходят строгую проверку полного комплекта. Удаление, пустой файл или неверный регистр по-прежнему блокируют сборку; эта защита сохраняется в изолированных тестах. Наличие записей не заменяет языковую приёмку и проверку звучания на телефоне.

`.build-check` — неполный технический артефакт, его нельзя публиковать. Команды preview не переключаются между каталогами автоматически. Не запускайте `preview` до успешного `build`; наличие старого `dist` не означает, что последняя сборка прошла.

Для проверки корня:

```sh
npm run build:check
npm run preview:check -- --port 4173 --strictPort
```

Для подкаталога остановите предыдущий preview и используйте одинаковую базу при сборке и просмотре:

```sh
VITE_BASE=/tamchy/ npm run build:check
VITE_BASE=/tamchy/ npm run preview:check -- --port 4173 --strictPort
```

Откройте `http://127.0.0.1:4173/tamchy/`. По умолчанию база `/`; её задаёт `VITE_BASE` в окружении, в компонентах имени репозитория нет. Для ресурсов используется `assetUrl()` с `import.meta.env.BASE_URL`. HTML также учитывает base.

## Структура и границы

```text
src/app/                 StrictMode, владелец сессии, экраны и hash-навигация
src/content/             catalog.json, tt.json, discriminated union LearningItem
src/domain/game/         модели, генератор, чистые переходы, требования к адаптерам и тесты
src/features/{home,game,parents}/  экраны; game также содержит useGameSession и исполнитель
src/shared/ui/           домик, локальные SVG и стили кнопок
src/services/assets/     URL, отменяемая подготовка и кэш декодированных изображений
src/services/audio/      ленивый AudioContext, единственная запись, PCM-кэш с LRU
src/styles/              общие стили и токены из ТЗ
scripts/lib/             Zod, файловые проверки, список ресурсов, плагин сборки
scripts/                 подготовка изображений и команды проверки контента
tests/integration/       проверки сборки, сессии и навигации настоящего App
tests/e2e/               браузерные проверки технического артефакта
tests/helpers/           управляемые браузерные границы только для тестов
assets-source/           неизменяемые мастер-PNG
public/assets/images/    производные WebP, создаются автоматически
public/icons/            производные иконки, создаются автоматически
public/assets/audio/tt/  30 учебных MP3 и 12 отложенных реплик
```

Node-скрипты запускаются встроенной поддержкой TypeScript в зафиксированной Node LTS. Конфигурации TypeScript разделены; инструменты подготовки не импортируются клиентским кодом. Домен отдельно проверяется без DOM, Node и Vite-глобалов; его импорты и обращения к внешним эффектам ограничены ESLint. Zod и sharp находятся в devDependencies. ESLint запрещает браузерному коду импортировать Node, скрипты, мастер-ресурсы и инструменты сборки; плагин дополнительно проверяет модули итогового bundle.

Каталог содержит разделы в порядке `colors`, `animals`, `numbers` и точный набор 4/6/5 элементов. Схема проверяет уникальность ID, вид элемента, принадлежность разделу, обязательные поля, цвета, значения чисел, назначение и имена ресурсов. Тест сверяет названия и полные задания с приложением A. Все исходные строки интерфейса из приложения A перенесены в `tt.json`; интерфейс и HTML-title используют этот словарь.

Проверка существования обходит каждый сегмент пути с точным регистром, отклоняет пустые файлы, каталоги и симлинки. Playwright дополнительно сверяет содержимое всех 30 учебных MP3 в `dist` с файлами в `public`, декодирует их и проверяет моно. Локально проверены формат и полное декодирование всех 42 записей. Произношение и качество звучания на телефоне требуют отдельной приёмки владельцем.

## Использование игровой сессии

`App` один раз вызывает `useGameSession()` над всеми экранами и напрямую связывает нажатие раздела с `game.start(category)`. Этот обработчик синхронно создаёт/возобновляет аудиоконтекст, создаёт новый `sessionId` и первый раунд вне рендера. Возвращаемые действия: `answer(id)`, `repeat()`, `retry()`, `continueGame()`, `exit()` и отдельное `activity()`. Для одного нажатия используется один `onClick`; не добавляйте независимый зачёт `touchend`.

Хук отправляет `ACTIVITY` перед ответом, повтором и продолжением. `exit()` немедленно отменяет операции и освобождает генератор; кэши адаптеров живут до unmount и могут пригодиться при следующем входе. `visibilitychange` и системное прерывание переводят сессию в паузу с немедленной остановкой. Возвращение не запускает звук; `continueGame()` снова активирует контекст из пользовательского обработчика. После ошибки `retry()` явно повторяет подготовку и проверяет разрешение звука. Состояние `error` содержит только доменную причину и ресурс.

Один экземпляр хука владеет одним аудиосервисом, сервисом изображений и текущим исполнителем. Независимые ресурсы раунда загружаются параллельно, готовность требует декодирования; весь каталог не загружается. Ограничение аудиокэша — 8 МиБ PCM, активный source удерживает свой буфер до остановки. Нет ни звуковых заглушек, ни синтеза речи. Подробности жизненного цикла и тестовых зависимостей — в [архитектуре](docs/architecture.md).

## Экраны и браузерная проверка

Маршруты: `#/`, `#/colors`, `#/animals`, `#/numbers`, `#/parents`. Неизвестный hash заменяется главным через `replaceState`; «Назад» и «Вперёд» работают между экранами. Раунды не добавляют записей в историю. Домик всегда открывает главный экран и останавливает сессию.

Нажатие раздела активирует аудио непосредственно в обработчике. Прямой адрес, перезагрузка и возврат в раздел через историю создают новую сессию с кнопкой «Тыңла». Повторное событие hash не перезапускает уже открытую сессию. Экран для взрослых показывает версию из `package.json`, сведения о данных и материалах и честное сообщение о текущей недоступности офлайна; кнопок установки и обновления пока нет.

```sh
npx playwright install chromium webkit firefox
npm run test:e2e
```

Команда сама последовательно выполняет строгий `build` для обеих баз в `dist` и запускает `preview` на `127.0.0.1:4173`, останавливая сервер перед следующей сборкой. Другой preview на этом порту должен быть остановлен. Можно передать фильтр: `npm run test:e2e -- --project=chromium`. Не запускайте одновременно несколько сборок в `dist`.

Проверки охватывают пять размеров окна, клавиатуру, увеличение текста до 200% и reduced motion. Скриншоты главного экрана, трёх разделов и информации для взрослых в размерах 390×844 и 768×1024 сохраняются в системном временном каталоге `tamchy-screenshots/`; путь можно задать переменной `TAMCHY_SCREENSHOTS`. Диагностика Playwright находится в системном временном каталоге `tamchy-e2e/`. Это материалы проверки, а не утверждённые визуальные эталоны. В обычных сценариях любой отказ ресурса проваливает тест. Только отдельный сценарий восстановления намеренно возвращает HTTP 503 для задания, затем снимает отказ и проверяет успешный повтор. Дополнительно проверяются полные циклы всех трёх разделов с настоящими заданиями, ошибками, подсказкой, повтором и подтверждениями.

## Графика

`assets:prepare` читает перечень изображений из проверенного каталога. Десять иллюстраций уменьшаются целиком с 1254×1254 до 768×768, без обрезания, затем кодируются sharp в WebP: quality 84, alphaQuality 100, effort 6. Каждая производная проверяется на формат, размеры, фактическую прозрачность и лимит 150 КиБ. Исходники не перезаписываются; SHA-256 всех 11 PNG сравниваются до и после обработки, в том числе при ошибке подготовки.

Обычные PNG-иконки имеют размеры 192, 512 и 180 пикселей. Производные используют палитру до 256 цветов с дизерингом и также проверяются на лимит 150 КиБ. У maskable отдельная композиция: исходное изображение целиком помещено в центр непрозрачного холста 512×512 в квадрат 288×288. Его диагональ меньше диаметра безопасного круга 80%, поэтому системная маска не обрежет значимые части.

Выходные файлы записываются атомарно только по известным путям. `public` и соседние материалы не очищаются. Повторная подготовка при зафиксированных зависимостях проверена сравнением хешей производных. Производные исключены из Git и воспроизводятся локально и в CI; мастер-PNG остаются в Git.

Vite не копирует весь `public`: плагин переносит только проверенные изображения, иконки и присутствующие обязательные учебные MP3. `.gitkeep`, `.DS_Store`, мастер-файлы, пользовательские посторонние материалы и отложенные реплики не попадают в артефакты.

## Добавление озвучки

1. Вычитать тексты и записать все 30 названий и полных заданий одним голосом по [реестру](docs/content-guide.md). Фразы записываются целиком.
2. При появлении исходных записей создать `assets-source/audio/tt/` и хранить оригиналы там, вне сборки.
3. Подготовить финальные моно MP3, ориентир 64–96 кбит/с; поместить в `public/assets/audio/tt/{colors,animals,numbers}/` с точными именами `*-label.mp3` и `*-prompt.mp3`. `.gitkeep` можно удалить только из заполненных каталогов.
4. Выполнить `npm run validate:content`. Пустые файлы и неполный набор не проходят проверку. Не создавать заглушки или копии одной записи.
5. До релиза добавить проверки формата/декодирования, получить проверку владельцем текстов, произношения, соответствия записей и звучания на телефоне; зафиксировать происхождение и условия использования материалов.

Все 12 реплик из `interaction/` добавлены и остаются отложенными: они не включены в учебный каталог, обязательную проверку или сборку. Подключение дополнительных реакций — отдельная задача по ТЗ.

## Подключённая озвучка

Все 42 предоставленных MP3 сохранены без перекодирования: 30 учебных записей работают в игре, 12 дополнительных реплик остаются отложенными. Учебные файлы занимают около 361 КиБ. `test:e2e` проверяет декодирование всех 30 записей и полные игровые циклы в Chromium, WebKit и Firefox против обычного `dist` для обеих баз.

После добавления записей прошли строгие сборки, 189 модульных/компонентных, 14 интеграционных и 66 браузерных сценариев. Описание формата, статуса приёмки и происхождения файлов — в [реестре контента](docs/content-guide.md), подробный результат — в [протоколе проверок](docs/testing.md).

## CI и проверенный объём

Workflow `Проверки проекта` выполняет `npm ci`, форматирование, lint, типы, модульные и интеграционные тесты, подготовку графики и строгую проверку контента на Linux. Затем устанавливает Chromium, WebKit и Firefox и запускает `test:e2e` со строгими сборками для `/` и `/tamchy/`. Официальные Actions закреплены по SHA; права ограничены чтением репозитория. Публикации нет. Защита от неполного комплекта сохранена в изолированном интеграционном тесте.

Это не полная приёмка MVP. Компонентные и интеграционные тесты экранов, домена и хука проверяют управление T01–T12; браузеры теперь проверяют также настоящие аудиозаписи, игровые циклы и части T17–T18. Устройства, воспринимаемое качество звука, PWA, офлайн, Lighthouse и публикация остаются непроверенными. Языковая приёмка и утверждение визуальных эталонов требуют владельца. Полный протокол — в [docs/testing.md](docs/testing.md).

Историческая проверка первого этапа 7 сентября 2026 года: macOS 26.6.2, Node 24.20.0, npm 11.19.0; `npm ci`, форматирование, lint, типы, 61 модульный/компонентный и 6 интеграционных тестов прошли. `npm audit` не обнаружил уязвимостей. В Chromium 146 через Playwright проверены dev и технические артефакты для обеих баз, перезагрузка, декодирование всех 14 графических ресурсов и отсутствие ошибок консоли; минимальный экран помещается в пять размеров окна из ТЗ. Хеши мастеров сверены также с Git, повторная генерация производных воспроизводима. Строгие `validate:content` и `build` завершились с кодом 1 и перечнем 30 отсутствующих MP3, `dist` не создан. Workflow на GitHub и настоящие Safari/iPhone/Android пока не запускались.

Проверка второго этапа на Node 24.20.0 и npm 11.19.0: 122 модульных/компонентных теста (61 тест домена) и 6 интеграционных тестов прошли; строки и ветви `domain/game` — 100%. Выполнены установка, форматирование, lint, проверка типов, каталог и обе технические сборки. Строгие `validate:content` и `build` по-прежнему отклоняют отсутствие 30 MP3. Полный протокол и ограничения — в [docs/testing.md](docs/testing.md). Минимальный экран и зависимости в этом этапе не менялись.

В третьем этапе сохранялись минимальный экран, домен и зависимости. Добавлены настоящие браузерные адаптеры, исполнитель требований, React-хук, тесты отмены и гонок. Протокол проверок и ограничения доказательств — в [docs/testing.md](docs/testing.md). Наличие тестового AudioContext не подтверждает настоящее звучание или поддержку Safari на iPhone.

Сборка явно нацелена на Safari 17. Dev-сервер Vite рассчитан на современный браузер; совместимость с минимальным Safari проверяется на собранном артефакте и впоследствии на реальном iPhone, а не заявляется по одному значению target.
