# Проверки «Тамчы»

## Объём четвёртого этапа

Проверяются чистый домен, настоящие реализации сервисов изображений и аудио, исполнитель `getGameRequirements` и `useGameSession`. Браузерные границы подменены только в тестах: fetch/Response, Image.decode и blob URL, AudioContext/AudioBufferSourceNode, видимость, монотонные часы. Управляемые Promise воспроизводят позднее завершение и зависание; Vitest fake timers заменяют время без реальных задержек.

Тесты первого и второго этапов сохранены: каталог, пути, ресурсы, графика, генератор и переходы, изолированные сборки Vite. Проверка минимального корня расширена проверками настоящего меню и экранов. Домен, gameReducer и getGameRequirements в интеграции не подменяются. `tests/integration/game-session.test.tsx` использует настоящий хук и сервисы через тестовый React-компонент; `user-event` нажимает кнопки, проверки наблюдают состояния, раунды, подсказку и остановку работы. Подменённый Web Audio не является доказательством настоящего воспроизведения.

`App` содержит главное меню, общий игровой экран с тремя представлениями ответов, информацию для взрослых и маршруты `#/`, `#/colors`, `#/animals`, `#/numbers`, `#/parents`. Новые компонентные и навигационные тесты используют эти экраны с настоящими доменом, хуком и адаптерами; подменяются только браузерные границы. Тестовые компоненты и браузерные подмены находятся в тестовых файлах и `tests/helpers`; в приложение и сборку они не импортируются. MP3-заглушки и демонстрационный режим не создавались.

После добавления MP3 браузерные проверки требуют успешную загрузку всех обязательных записей и отсутствие неожиданных ошибок ресурсов. PWA и офлайн остаются вне текущей проверки.

## TDD и покрытие

Критерии сначала выражались тестами. В третьем этапе первые запуски воспроизвели отсутствие адаптеров/исполнителя/хука; отдельные падающие тесты затем воспроизвели пропуск просроченного успеха при задержанном таймере и проигнорированный домик после ответа в одном React-пакете. Исправлены только новые модули интеграции; домен второго этапа не менялся. До реализации соответствующие запуски завершались ошибкой отсутствующего модуля или несовпадением ожидаемого перехода; затем добавлялась реализация. Отдельный тест воспроизвёл исчезновение подсказки при ошибке ресурса/паузе до ответа, после чего вычисляемый признак исправлен. Тестовые ожидания ради успешного результата не ослаблялись.

`npm run test:unit -- --coverage` включает прежние области, все исходники `src/domain/game/**/*.ts`, `src/services/{assets,audio}/**/*.ts` и `src/features/**/*.{ts,tsx}`, `src/app/**/*.{ts,tsx}` и `src/shared/ui/**/*.tsx`, исключая тесты. Хук и браузерные адаптеры включены в отчёт, даже если отдельные ветви исполняются только интеграционным набором. Для каждого файла домена установлены **строки ≥90% и ветви ≥90%** через отдельный glob и `perFile: true`; покрытие других областей не компенсирует недостаток домена. Типовой `models.ts` не содержит исполняемых строк и ветвей.

Обязательность порога дополнительно проверена временным непокрытым файлом домена: команда завершилась с кодом 1 и отдельными ошибками порогов строк и ветвей именно этого файла. Проверочный файл удалён; он не входит в проект. Запреты ESLint проверены также отрицательными пробами импорта React, Node, браузерного сервиса, динамического импорта, обращения к `Date.now` и `Math.random`.

Отчёты создаются в `coverage/` и исключены из Git: таблица в консоли, HTML, JSON, JSON summary и Clover. Высокий процент не заменяет перечисленные сценарии и интеграционные проверки.

## Команды и CI

Среда — закреплённые Node.js 24.20.0 и npm 11.19.0. Текущая последовательность проверки:

```sh
npm ci
npm run format:check
npm run lint
npm run typecheck
npm run test:unit -- --coverage
npm run test:integration
npm run validate:content
npx playwright install chromium webkit firefox
npm run test:e2e
git diff --check
```

Существующий workflow `Проверки проекта` запускает эти npm-проверки на Linux с Node из `.nvmrc`. Новые тесты автоматически входят в существующий glob; пороги покрытия обязательны для той же команды в CI. Сохраняется отдельная проверка типов домена без браузерных глобалов. TSX-интеграция и браузерные подмены проверяются браузерным tsconfig, Node-сборки — отдельным конфигом. CI также запускает git diff --check. Права workflow, закреплённые Actions и запрет публикации не менялись.

Технические сборки последовательно записывают `.build-check`; это неполный артефакт, который нельзя публиковать. Шесть интеграционных тестов первого этапа выполняют реальные изолированные сборки Vite и проверяют в том числе строгую блокировку неполного контента. Они не требуют наличия настоящих MP3 в репозитории и не доказывают воспроизведение.

## Результат и ограничения

Исторический результат второго этапа: 122 модульных/компонентных теста, из них 61 тест домена, и 6 интеграционных тестов успешны. Покрытие `domain/game`: строки 100%, ветви 100%, функции 100%. Полный список команд приведён выше. `npm ci` не потребовал изменения зависимостей; аудит сообщил 0 уязвимостей.

Реальные 30 обязательных учебных MP3 отсутствуют. `validate:catalog` сообщает о неполном аудиоконтенте; строгие `validate:content` и `build` сохраняют ожидаемый отказ с кодом 1. Аудиофайлы и заглушки в этом этапе не создавались. ТЗ не изменялось.

Результат третьего этапа 7 сентября 2026 года на macOS, Node 24.20.0, npm 11.19.0: 164 модульных/компонентных и 11 интеграционных тестов (5 сценариев сессии и 6 сборочных) прошли. Покрытие строк и ветвей domain/game — 100%; пороги ≥90% на каждый файл сохранены. Выполнены npm ci, format:check, lint, typecheck, test:unit с покрытием, test:integration, validate:catalog, build:check для `/` и `/tamchy/`, git diff --check. Зависимости и lock-файл не менялись. Строгий файловый барьер проверяется интеграционными сборками; отсутствие 30 MP3 продолжает блокировать релиз.

На конец третьего этапа не были выполнены игровые экраны и маршрутизация; они добавлены в четвёртом. PWA, офлайн, дополнительные интерактивные реплики и публикация всё ещё не реализованы. Не проверены: настоящее декодирование учебных MP3 и слышимость, физическая отмена операций на устройствах, касания, громкость/беззвучный режим ОС, реальные Safari/iPhone/Android, установка и обновления, Lighthouse, приёмка материалов владельцем и наблюдение за детьми. Workflow на GitHub в рамках локальной работы не запускался. Владение ресурсами и использование хука описаны в [архитектуре](architecture.md).

Домик проверяется при подготовке, реакциях, паузе и ошибке; прежний доменный тест выхода охватывает также переход. Адрес и длина истории не меняются после правильного ответа и перехода раунда. Повторное уведомление hash/popstate и новый объект options не меняют владельца или источник звука.

Падающие тесты четвёртого этапа воспроизвели отсутствие экранов, пересоздание сервисов при новом options и проигнорированную ошибку картинки после подготовки. Сохранена проверка настоящего cleanup/setup: вместо прежней замены options её теперь вызывает React Activity. Контракт options намеренно изменён на фиксацию конфигурации при mount. Строгость словаря проверяется удалением, пустым значением и лишним ключом в каждой группе.

## Playwright и визуальные свидетельства

`npm run test:e2e` через `scripts/test-e2e.ts` последовательно выполняет строгий `build` для `/`, запускает Playwright и `preview`, затем останавливает preview и повторяет для `/tamchy/`. Два процесса не пишут в `dist` одновременно. `playwright.config.ts` запрещает повторы нестабильных тестов (`retries: 0`) и использование занятого preview-порта. В CI устанавливаются все три браузера через `npx playwright install --with-deps chromium webkit firefox`; прежние проверки сохранены.

Chromium и WebKit проверяют размеры 320×568, 390×844, 768×1024, 1024×768 и 844×390. Firefox выполняет основные настольные переходы, ошибки, историю и клавиатуру; мобильная компоновка в его проекте явно пропускается. Успешные игровые сценарии в Playwright не имитируются: настоящий Web Audio декодирует предоставленные записи и проводит полный цикл каждого раздела. Отдельный тест сверяет все 30 файлов с оригиналами по SHA-256 и проверяет число каналов и ненулевую длительность. Это не проверка воспринимаемого качества звука на телефоне или офлайна.

Скриншоты десяти сочетаний экран/телефон/планшет сохраняются в системный временный `tamchy-screenshots/`, либо в `TAMCHY_SCREENSHOTS`. Следы отказов и вложения `injected-audio-failures` отдельного негативного сценария находятся в `tamchy-e2e/{root,subpath}/` того же временного каталога. Эталонные снимки в Git пока не закрепляются. Для локального просмотра нужна та же база и `preview:check`; запуск workflow на GitHub отдельно не выполнялся.

Успешны `npm ci`, `format:check`, `lint`, `typecheck`, 189 модульных/компонентных тестов с покрытием и 14 интеграционных тестов. Покрытие `domain/game`: строки 100%, ветви 99,57%; обязательные пороги ≥90% на каждый файл сохранены. Новые TSX-экраны входят в отчёт покрытия.

`validate:catalog` и технические сборки для `/` и `/tamchy/` успешны. Полный `test:e2e` последовательно проверил обе базы через `preview:check`: по 21 успешному сценарию на базу, всего 42. Ещё по шесть проверок мобильной компоновки и увеличения текста намеренно пропущены в проекте Firefox; эти сценарии выполнены Chromium и WebKit. Использованы Playwright 1.63.0, Chromium 153.0.8010.12, WebKit 26.6 и Firefox 155.0. Неожиданных ошибок приложения не обнаружено; отказы отсутствующих MP3 учтены отдельно.

Осмотрены все десять снимков главного экрана, трёх разделов и информации для взрослых на телефоне 390×844 и планшете 768×1024. Дополнительно проверены все пять требуемых размеров окна, увеличение текста до 200% на 320×568, reduced motion и сохранение карточек при смене ориентации. Браузерные регрессии сначала воспроизвели выход карточек за ширину окна и содержимого числовой карточки за её нижний край; после исправления проверки проходят. Яблоки полностью помещаются внутри кнопок и сохраняют одинаковый размер. Визуальные эталоны и новые татарские тексты требуют отдельного утверждения владельцем.

Строгие `validate:content` и `build` ожидаемо завершаются с кодом 1 из-за всех 30 отсутствующих учебных MP3. Технический артефакт не публиковался. Настоящее воспроизведение, физические телефоны, Lighthouse, PWA, офлайн и обновления этим результатом не подтверждены. `git diff --check` выполнен перед локальным коммитом.

## Подключение реальных аудиозаписей

Владелец добавил 42 MP3; 30 обязательных записей автоматически подключаются существующим каталогом и входят в `dist`, 12 реплик `interaction/` остаются отложенными. Из заполненных каталогов удалены `.gitkeep`. Сверка SHA-256 подтвердила, что все предоставленные файлы сохранены без изменений.

Первый запуск прежнего браузерного сценария воспроизвёл устаревшее ожидание: тест ждал ошибку отсутствующего файла, но получил HTTP 200 и готовую игру. Сценарий восстановления теперь намеренно возвращает HTTP 503, проверяет блокировку ответов, снимает отказ и проверяет успешную загрузку по кнопке повтора. Общий наблюдатель больше не допускает любые отказы MP3: исключение разрешено только явно перечисленным адресам негативного сценария.

Новые проверки используют настоящие Web Audio и файлы из обычной сборки:

- Все 30 учебных MP3 загружаются, совпадают по SHA-256 с файлами из `public`, декодируются и имеют один канал и ненулевую длительность.
- Полный цикл каждого раздела проходит все 4/6/5 целей без повторения; зафиксированы запросы каждого задания и подтверждения.
- Проверены неправильные ответы, сохранение вариантов, подсказка после двух ошибок, ручной повтор, правильный ответ и переход после окончания подтверждения.
- Раунды не добавляют историю; домик возвращает в главное меню. Неожиданные ошибки console/pageerror, ответы HTTP ≥400 и внешние запросы проваливают успешные сценарии.

Локальный результат 7 сентября 2026 года, Node 24.20.0 и npm 11.19.0: установка, lint, типы, 189 модульных/компонентных и 14 интеграционных тестов успешны. Покрытие `domain/game`: строки 100%, ветви 99,57%. Строгие `validate:content` и `build` проходят для `/` и `/tamchy/`.

Playwright: по 33 успешных сценария на базу, всего 66 в Chromium, WebKit и Firefox. По шесть прежних проверок мобильной компоновки намеренно пропущены в Firefox; они выполнены Chromium и WebKit. Все 30 учебных файлов декодируются в каждом браузере на обеих базах. Осмотрены снимки работающих животных на 390×844 и чисел на 768×1024: нет обрезанных объектов, перекрытий и экрана ошибки.

Дополнительно ffprobe и ffmpeg подтвердили формат MP3, моно, 48 кГц, 96 кбит/с и полное декодирование всех 42 записей. Учебный комплект — 369 384 байта. Сборка для подкаталога содержит 47 файлов, включая 30 учебных MP3; размер 1 373 363 байта, JS gzip — 69 111 байт, CSS gzip — 2 198 байт. Бюджеты этих размеров выполнены; исходники, служебные файлы и дополнительные реплики не попали в артефакт.

Проверка воспринимаемой громкости, произношения и звучания на физических iPhone/Android остаётся за приёмкой на устройствах. PWA, офлайн, обновления, Lighthouse и публикация не реализованы или не проверены этой работой; успешная сборка не объявляется полной готовностью MVP. Предыдущие результаты этапов выше относятся к состоянию до добавления MP3.
