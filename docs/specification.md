# «Тамчы»: техническое задание на MVP

**Версия:** 1.0  
**Дата:** 7 сентября 2026 года  
**Формат:** статическое PWA на GitHub Pages, без собственного бэкенда.  
**Метод разработки:** TDD — разработка через тесты.

## 0. Основание и статус решений

Основа — согласованная в переписке концепция: полностью татарское приложение для детей 2–3 лет, разделы «Төсләр», «Хайваннар», «Саннар», дизайн «игрушечные карточки», самостоятельная игра простыми нажатиями, без аккаунтов и прогресса. Иллюстрации владелец генерирует отдельно, озвучку записывает самостоятельно.

Исходный Markdown-документ из соседнего чата среди доступных файлов не найден; этот документ не является его дословным продолжением.

**Параметры, которые ранее не были окончательно определены и фиксируются настоящим ТЗ:** четыре цвета, шесть животных, числа 1–5, два варианта ответа, один общий тип игры «найди по озвучке», React + TypeScript + Vite. Служебный экран для взрослых добавляется только для установки, состояния офлайн-загрузки, обновления и информации о приложении.

Все требования обязательны для MVP, кроме явно помеченных как последующее развитие. Численные размеры, задержки, бюджеты и пороги покрытия ниже — проектные требования, а не утверждения об универсальных возрастных нормах.

---

## 1. Назначение и границы

Приложение знакомит ребёнка с татарскими названиями цветов, животных и чисел через короткие озвученные задания и выбор крупной картинки. Для основных действий не требуется чтение.

Взрослый выполняет первое открытие с интернетом, при необходимости устанавливает приложение и проверяет звук. После этого ребёнок должен самостоятельно выбирать раздел, отвечать, повторять задание и возвращаться в меню. Удобство для возраста 2–3 лет проверяется наблюдением; оно не считается доказанным одними размерами кнопок.

В MVP входят три раздела, общая игровая механика, озвучка, адаптивный интерфейс, установка PWA и офлайн-работа после полной подготовки ресурсов.

**Не входят:** регистрация, аккаунты, статистика, сохранённый прогресс, очки, уровни, достижения, рейтинги, ежедневные серии, реклама, покупки, уведомления, фоновая музыка, распознавание речи, генерация контента во время игры, перетаскивание, обязательные свайпы, сказки и диалоги. Отдельный режим свободного знакомства и игра по голосам животных также не входят.

Нет отдельной рекламной посадочной страницы: корневой адрес сразу открывает приложение.

## 2. Стартовый контент и правила разделов

| Раздел | Состав MVP | Варианты на экране |
|---|---|---|
| Төсләр | Кызыл, сары, яшел, зәңгәр | Две одинаковые по форме и размеру игровые фишки разных цветов |
| Хайваннар | Мәче, эт, сыер, ат, сарык, үрдәк | Две иллюстрации разных животных |
| Саннар | Бер, ике, өч, дүрт, биш | Две карточки: цифра и соответствующая ей группа яблок |

Количество вариантов всегда равно двум. Оно не увеличивается автоматически и не зависит от ответов ребёнка.

### 2.1. Цвета

Задание, например: «Кызыл төсне тап».

Форма, размер, фон и оформление двух вариантов одинаковы; различается только учебный цвет. Использовать программно окрашиваемую SVG-форму либо CSS-фишку. Это намеренное исключение из генерируемых иллюстраций: оттенок задаётся точным значением в данных, а не результатом генерации.

На фишках нет лиц, цифр и узнаваемых предметов, подсказывающих ответ. Пастельное оформление приложения не должно превращать красный в розовый, а синий — в почти белый.

### 2.2. Животные

Задание, например: «Мәчене тап».

Животное изображается целиком, без обрезанных частей тела, посторонних предметов и фона. Размер изображения и сложность иллюстрации не обозначают правильный ответ. Допускается условный игрушечный стиль при сохранении узнаваемости.

### 2.3. Числа

Задание, например: «Өч алманы тап».

Цифра выводится обычным текстом; количество яблок создаётся кодом повторением одной иллюстрации. Нельзя использовать сгенерированную картинку с уже нарисованным количеством предметов.

В обеих карточках одинаковы размер яблока, цвет, масштаб цифры и доступная область. Предметы не перекрываются. Для 1–5 используются заранее заданные расположения в пределах общей сетки. Невидимые позиции не обозначаются рамками или дополнительными точками.

## 3. Экраны и навигация

### 3.1. Главный экран

Название «Тамчы», три крупные карточки в неизменном порядке: «Төсләр», «Хайваннар», «Саннар». На каждой — иллюстрация и вторичная текстовая подпись.

Нажатие на карточку открывает игру без промежуточного выбора режима. Первое касание одновременно используется для активации аудио. В обычном сценарии дополнительная кнопка «Начать» не появляется.

На главном экране разрешена одна визуально вторичная кнопка информации для взрослых. Не добавлять нижнюю панель вкладок, профиль, карусель, поиск и меню с вложенными разделами.

### 3.2. Игровой экран

Сверху находятся кнопка-домик, название раздела и кнопка повторного прослушивания. Основную площадь занимают два варианта ответа. Короткое татарское задание показывается текстом и озвучивается; чтение не требуется.

Реакция на ответ отображается здесь же, без отдельного окна. Кнопка-домик остаётся доступной при загрузке, воспроизведении, ошибке и переходе между заданиями.

### 3.3. Информация для взрослых

Один простой экран: установка приложения, состояние подготовки офлайн-версии, повтор загрузки при ошибке, версия приложения, доступное обновление, краткая информация о данных и материалах.

Вход обычным нажатием, без пароля и длинного удержания. В MVP экран не содержит покупок, удаления данных, внешних переходов или других опасных действий. Возврат на главный экран всегда очевиден.

Инструкция по установке не появляется автоматически поверх игры. На iPhone установка выполняется средствами Safari; названия системных пунктов зависят от языка ОС. Собственный интерфейс приложения остаётся татарским. [S7]

### 3.4. Адреса и история

Использовать маршруты во фрагменте адреса: `#/`, `#/colors`, `#/animals`, `#/numbers`, `#/parents`. Это проектное решение для размещения на статическом хостинге без серверных перенаправлений.

Обновление адреса раздела открывает этот раздел с новой игровой сессией. Запуск установленного приложения через `start_url` ведёт на главный экран. Неизвестный маршрут безопасно заменяется главным экраном.

Кнопка браузера «Назад» возвращает между экранами, а не между заданиями. Новое задание не добавляет запись в историю. При прямом входе в раздел домик открывает главный экран независимо от истории браузера. Системные жесты и выход из приложения не блокируются.

После перезагрузки страницы аудио может требовать нового касания: показать крупную кнопку воспроизведения и не принимать ответы, пока задание не готово к озвучиванию.

## 4. Поведение игры

### 4.1. Один раунд

1. Подготовить задание, две картинки и обязательную озвучку.
2. Показать варианты и начать озвучку. После начала воспроизведения разрешить ответ, не требуя дослушивать фразу.
3. Обработать первое допустимое нажатие.
4. Показать реакцию и либо оставить задание, либо перейти к следующему.

Термин «раунд» означает одно задание, а не уровень. Раунд не ограничен временем.

**Правильный ответ:** отменить текущую фразу, выделить выбранную карточку, показать небольшой знак подтверждения и произнести название или число. Следующее задание появляется не раньше чем через 1200 мс после ответа и не раньше чем через 300 мс после окончания подтверждающей озвучки. Выполняются оба условия. Во время реакции ответы заблокированы.

**Неправильный ответ:** коротко обозначить касание без красного экрана, неприятного звука, потери чего-либо и перестановки карточек. После визуальной реакции длительностью 250 мс произнести предусмотренную реплику из раздела 4.1.1, затем повторить исходное задание. Правильный вариант не меняется.

После двух неправильных ответов в текущем раунде правильная карточка получает статичную ненавязчивую обводку до ответа. Автоматически отвечать за ребёнка нельзя.

**Повтор:** прервать текущую фразу и воспроизвести задание сначала. Запросы не ставятся в очередь. Кнопка повтора не действует во время подтверждения правильного ответа.

**Бездействие:** спустя 10 секунд после окончания задания повторить его один раз за раунд. Затем ждать без бесконечных призывов, мигания и автоперехода. Любое действие отменяет текущий таймер бездействия.

Игровой цикл продолжается, пока ребёнок отвечает или не выйдет домой. Нет итогового экрана, счётчика выполненных заданий и механик принудительного удержания.

### 4.1.1. Интерактивные реплики

После первого релиза по запросу владельца подключены все 12 записей `interaction/`. События используют следующую политику, общую для трёх разделов:

| Действие | Реплика и последовательность |
|---|---|
| Первый вход в раздел после открытия приложения | `hello` → задание; на главном экране автозвука нет |
| Следующий вход в любой раздел | `game-start` → задание |
| Правильный ответ | В нечётных раундах по кругу `correct`, `well-done`, `very-good` → название; в чётных — только название |
| Ошибка в текущем раунде | После 250 мс: первая — `think-again`, вторая — `hint`, третья — `try-again`, затем без реплики; после каждой снова полное задание |
| Единственное напоминание через 10 секунд | `listen` → задание |
| Каждый пятый новый раунд | `next-one` → задание |
| Продолжение после паузы до ответа | `continue` → исходное задание; после принятого ответа сохраняется один переход без повторного подтверждения |
| Кнопка повтора | Только исходное задание, с отменой текущей реплики |
| Домик из игры | Немедленный переход домой и `goodbye`; браузерная навигация и экран взрослых не произносят прощание |

Вступительная реплика не разрешает ответы: необходим фактический старт учебного задания. Похвала не заменяет название; 300 мс отсчитываются после окончания названия, также сохраняются 1200 мс после ответа. Последовательность принадлежит одной отменяемой операции: повтор, выход, новая сессия и пауза не оставляют отложенного звука. Прощание тоже прерывается новым входом, уходом с главного экрана, скрытием страницы и системным прерыванием; оно не задерживает навигацию.

В релизе обязательны все 42 MP3. Во время игры ошибка загрузки/декодирования дополнительной реплики либо ожидание её загрузки более 2 секунд пропускает реплику и сохраняет учебную запись. Запрет звука и системное прерывание обрабатываются обычным восстановлением аудио. Ошибки обязательных учебных записей по-прежнему блокируют ответы до явного повтора. Прощание при ошибке пропускается, его ожидание ограничено 15 секундами.

### 4.2. Генерация

Каждый элемент раздела становится целью один раз за перемешанный цикл. После исчерпания набора он перемешивается заново; цель на границе двух циклов не повторяется подряд.

Вариант-помеха выбирается из остальных элементов того же раздела. Варианты различны, правильный ответ ровно один. Расположение перемешивается независимо; не использовать постоянное место или строгое чередование правильного ответа.

Случайность передаётся генератору как зависимость. В тестах применяется фиксированный источник случайности. Не использовать случайность при отрисовке компонентов или внутри функции переходов состояния.

### 4.3. Защита от повторных действий

Быстрые и одновременные касания не создают несколько переходов, наложенную озвучку или ответ на ещё не показанный раунд. На одном элементе нельзя независимо засчитывать и событие касания, и последующее событие клика.

Каждое асинхронное действие привязано к идентификаторам сессии и раунда. Результаты устаревшего запроса, таймера или аудио игнорируются. Выход из игры отменяет связанные действия.

## 5. Визуальная система и доступность

### 5.1. Стиль

«Игрушечные карточки»: светлый спокойный фон, округлые формы, крупные иллюстрации, свободное пространство, минимум декора. Без объёмных глянцевых эффектов, постоянной анимации и перегруженной сцены.

Татарский характер прежде всего задаётся языком и содержанием. Орнамент возможен только как необязательный малозаметный декор вне учебных объектов и управляющих элементов.

Базовые проектные токены:

| Назначение | Значение |
|---|---|
| Фон приложения | `#FFF9F2` |
| Основная поверхность | `#FFFFFF` |
| Текст и основные значки | `#27332F` |
| Мягкие акценты | `#E3F0E6`, `#FBE6D9`, `#E1EDF7` |
| Учебные цвета | Красный `#D94343`, жёлтый `#F3C63A`, зелёный `#32965B`, синий `#347FD4` |
| Базовый шаг отступов | 8 CSS-пикселей |
| Скругление крупных карточек | 24–32 CSS-пикселя |

Токены централизованы. Изменение палитры не требует редактирования отдельных экранов. Эти значения выбраны для реализации и не считаются извлечёнными из ранее созданного эталонного изображения.

### 5.2. Размеры и компоновка

Область нажатия служебной кнопки — не менее 56×56 CSS-пикселей. Игровой вариант — не менее 128×128; промежуток между вариантами — не менее 16. Карточка раздела на компактном телефоне — высотой не менее 112.

В портретном телефоне три раздела располагаются вертикально. В широком окне возможны три столбца. Два игровых варианта размещаются рядом либо вертикально — в зависимости от доступной высоты и ширины, без уменьшения ниже установленного минимума.

Проверяемые размеры области просмотра: 320×568, 390×844, 768×1024, 1024×768 и 844×390. На стандартном масштабе главный и игровой экраны не требуют прокрутки. При увеличении текста допускается вертикальная прокрутка вместо обрезания.

Учитывать вырезы и системные области через `safe-area-inset-*`, изменяемую высоту окна через `dvh` с резервным вариантом. Не блокировать ориентацию и не требовать перехода в полноэкранный режим браузера.

### 5.3. Текст, управление и движение

Использовать системный шрифт без сетевой загрузки. Проверить символы `Ә ә Ө ө Ү ү Җ җ Ң ң Һ һ`. Обычные подписи — от 20, названия разделов — от 24, служебный текст для взрослых — от 16 CSS-пикселей. Текст не запекать в изображения.

Использовать настоящие кнопки, татарские доступные названия, видимый клавиатурный фокус и последовательную навигацию. Поддержать Tab, Enter и Space. Декоративные изображения не должны повторно озвучивать название кнопки.

Контраст обычного текста — не менее 4,5:1; необходимой графики управления и индикаторов состояния — не менее 3:1. Правильность ответа не обозначается только цветом. Учебное различение цветов не подменять обещанием полной доступности этой конкретной игры для всех нарушений цветового восприятия. [S8]

При `prefers-reduced-motion` отключить масштабирование и перемещения, сохранив статичную реакцию. Обычная реакция на нажатие занимает 100–160 мс; игровая анимация — не более 400 мс. Не запрещать масштабирование страницы пользователем.

Комплект содержит 30 учебных аудиофайлов и 12 интерактивных реплик. Подтверждение использует запись названия; отдельные аплодисменты, музыка и голоса животных не требуются.

### 6.2. Подготовка

Иллюстрации: общий утверждённый эталон стиля, прозрачный фон, квадратный холст, объект без обрезания, сопоставимый визуальный масштаб. Оригинальные мастер-PNG хранятся без изменения качества в `assets-source/`. Перед релизной сборкой контентные PNG автоматически конвертируются в оптимизированный WebP с сохранением прозрачности и без обрезания объектов. Значки интерфейса — локальные SVG.

Из `assets-source/icons/app-icon-master.png` автоматически создаются необходимые PWA- и iOS-иконки: 192×192, 512×512, отдельный маскируемый значок и Apple Touch Icon 180×180. Мастер иконки имеет непрозрачный фон. Приложение во время работы использует только производные ресурсы и не загружает PNG из `assets-source/`; мастер-исходники не включаются в `dist`.

Фактический перечень мастер-файлов, назначение каждого ресурса, пути производных и текущий статус подготовки зафиксированы в [руководстве по контенту](content-guide.md). Автоматическая конвертация и генерация иконок реализованы командой `npm run assets:prepare`.

Озвучка: один голос, естественный татарский язык, одинаковый темп и воспринимаемая громкость, без фонового шума, щелчков, перегрузки и длинной тишины. Публикуемый формат — MP3, моно, ориентир 64–96 кбит/с; исходная запись хранится отдельно от сборки. Финальный критерий — разборчивость на динамике телефона, а не только параметры кодирования.

Полные фразы записывать отдельными файлами. Не собирать падежные формы и предложения склейкой слов во время игры. Не использовать сетевой синтез речи.

Владелец проверяет соответствие каждой картинки, текста и записи до включения в релиз. Наличие файла само по себе не доказывает правильность языка или произношения.

## 7. Язык и тексты

Весь собственный интерфейс, задания, ошибки, информация для взрослых и доступные названия — на татарском. Установить `lang="tt"`, направление слева направо. Русские пояснения разрешены только в документации разработчика.

Все строки находятся в одном словаре `tt.json`; текст не дублируется в компонентах. Для контента хранятся полные названия и полные задания. Библиотека многоязычности и переключатель языка не нужны.

Приложение не управляет языком меню Safari, Android и других системных окон. Это не считается нарушением требования к языку собственного интерфейса.

Перечень учебных фраз приведён в приложении A. Перед записью обязательна окончательная языковая вычитка, включая ударение и произношение.

## 9. Архитектура и данные

### 9.1. Разделение ответственности

**Контент → чистая игровая логика → экран игры → браузерные адаптеры.**

Чистая логика не импортирует React, DOM, звук, хранилище и сеть. Компоненты отображают состояние и отправляют события. Адаптеры управляют аудио, загрузкой ресурсов, таймерами и PWA.

Три раздела используют общий механизм раундов и проверки ответа. Отличается представление варианта: фишка, животное или группа предметов. Новая тема с той же механикой добавляется данными, а действительно новая механика — отдельной реализацией, не разрастанием одного универсального компонента.

Состояние должно исключать взаимоисключающие комбинации. Производные значения вычисляются, а не хранятся второй копией. [S1]

### 9.2. Структура

Целевая структура проекта; фактический состав графики и планируемый каталог озвучки приведены в [руководстве по контенту](content-guide.md).

В `public/assets/audio/tt/` добавлены все 30 обязательных учебных MP3 и 12 дополнительных реплик по руководству по контенту. Учебные записи используются через существующие `labelAudio` / `promptAudio` и включаются в сборку. ### 9.3. Модель учебного элемента

Общие поля: `id`, `kind`, `labelTt`, `promptTt`, `labelAudio`, `promptAudio`.

Специализированные поля:

| `kind` | Обязательные дополнительные данные |
|---|---|
| `color` | `hex` — значение цвета |
| `animal` | `image` — путь иллюстрации |
| `number` | `value` — целое 1–5; `countImage` — общая иллюстрация яблока |

В TypeScript использовать объединение типов с признаком `kind`, а не объект, в котором все специализированные поля необязательны. Пути относительные, без ведущего `/`, без внешних адресов и переходов `..`.

Пути иллюстраций указывают на готовые WebP в `assets/images/`, без префиксов `public/`, `dist/` и `assets-source/`; они разрешаются с учётом базового адреса приложения из раздела 13.

Раунд содержит `roundId`, `categoryId`, `targetId`, `optionIds`. Проверка ответа выполняется по идентификаторам, не по подписи, цвету, имени файла или позиции.

### 9.4. Проверка контента

Сборка завершается ошибкой при повторяющемся ID, неверном типе, недостающем переводе, неизвестной категории, числе вне диапазона, неверном цвете, отсутствующем файле или неполном наборе озвучки.

Проверять регистр путей на Linux, существование ресурсов в итоговой сборке, соответствие перечня обязательных ресурсов списку предварительного кэширования, размеры файлов и отсутствие внешних зависимостей. Сгенерированные манифесты не редактировать вручную.

Проверка ресурсов должна отклонять сборку, содержащую `assets-source/` или оригинальные мастер-PNG. В итоговую сборку и офлайн-набор включаются производные WebP и необходимые сгенерированные иконки.

Состояние сессии хранится только в памяти. После закрытия страницы оно не восстанавливается. Для раундов и результатов `localStorage` и IndexedDB не нужны.

## 10. Состояния и восстановление

Состояния игры: подготовка, ожидание ответа, правильный ответ, повторная попытка, переход, пауза, ошибка. Переходы реализованы одной чистой функцией; события, недопустимые для текущего состояния, игнорируются.

| Ситуация | Требуемое поведение |
|---|---|
| Быстрые касания в одном раунде | Один принятый ответ, не более одного перехода |
| Выход домой во время звука | Немедленная отмена звука, запросов и таймеров этой сессии |
| Смена ориентации | Перекомпоновка без смены задания и перестановки ответов |
| Сворачивание или блокировка | Остановка звука и таймеров, сохранение состояния в памяти |
| Возврат из фона | Крупная кнопка продолжения, без неожиданного звука |
| Пауза до ответа | После продолжения тот же раунд и повтор задания |
| Пауза после принятого правильного ответа | После продолжения один переход к следующему раунду, без повторного зачёта |
| Отсутствующая картинка | Не принимать ответы по неполным вариантам; повтор и домик |
| Ошибка обязательной озвучки | Пауза с повтором; не выдавать новую задачу без звука |
| Ошибка необязательного декора | Основная игра продолжается |

Состояние ошибки хранит контекст восстановления: какой ресурс и какую фазу нужно повторить. Ошибка подтверждающей записи после правильного ответа не отменяет уже принятый ответ и не засчитывает его второй раз.

Повтор загрузки ограничивается явным действием пользователя; не создавать бесконечный цикл сетевых запросов. Для загрузки обязательного ресурса установить контролируемый тайм-аут 15 секунд. Технические сообщения и стеки ошибок ребёнку не показываются.

## 11. Аудиосистема

Один сервис управляет одним `AudioContext`. Короткие MP3 загружаются полностью через `fetch`, декодируются через `decodeAudioData` и воспроизводятся из буфера. Метод декодирования требует полного файла, а не фрагмента потока. [S3]

Создание/возобновление контекста запускается непосредственно из обработчика касания — до ожидания сетевых операций. Результат проверяется. При запрете воспроизведения показывается крупный активатор звука; нельзя считать одно касание гарантией разрешения звука навсегда. Браузерные ограничения автозапуска обрабатываются явно. [S2]

Одновременно звучит не более одной записи. Повтор, ответ, переход и выход отменяют прежнюю запись и её обработчики завершения. Отмена не трактуется как успешное завершение.

При скрытии страницы и системном прерывании звук останавливается. После возвращения контекст проверяется и при необходимости возобновляется касанием. Зависший вызов не должен блокировать домик и повтор. [S4]

На диске допускается весь офлайн-набор, но в оперативной памяти не следует декодировать всю библиотеку. Подготавливаются текущие и ближайшие записи; кэш декодированного аудио ограничен, например 8 МиБ, и освобождает давно не использованные буферы.

Громкость и беззвучный режим устройства остаются под управлением ОС. В приложении нет обещания обойти эти настройки.

## 12. PWA и офлайн

### 12.1. Установка

Обязателен манифест: стабильный `id`, `name` и `short_name` «Тамчы», `lang: tt`, `start_url`, `scope`, `display: standalone`, согласованные цвета и значки. Не фиксировать ориентацию. Добавить Apple touch icon. Проверить обычный браузерный и установленный режимы. [S5]

На iPhone инструкция описывает системное добавление через Safari. На Android использовать браузерную установку, когда она доступна; отсутствие программного приглашения не должно блокировать приложение. [S5, S7]

### 12.2. Первая загрузка

Сначала показывается работоспособная оболочка. Затем автоматически загружается полный набор MVP. Это не должно блокировать доступную онлайн-игру; текущие игровые ресурсы имеют приоритет перед дополнительной подготовкой.

Предварительно кэшируются HTML, JS, CSS, словари, все учебные изображения, все 42 записи (30 учебных и 12 интерактивных) и необходимые значки. Файлы MP3 и WebP включаются в список явно: наличие файла в `public` само по себе не принимается за доказательство включения в офлайн-набор. [S6]

Офлайн-готовность устанавливается только после успешной установки service worker и подтверждения полного набора обязательных файлов для текущей версии. Произвольного флага в `localStorage` недостаточно. В родительском экране показывать честное состояние: подготовка, готово либо ошибка с повтором; процент не выдумывать.

### 12.3. Гарантия и ограничения

После полной подготовки все три игры, включая ранее не открывавшиеся задания и аудио, работают без сети при повторном запуске и обновлении страницы. Приёмка проводится в том же браузерном/установленном контексте, в котором ресурсы подготовлены.

Если при первом открытии нет сети и оболочка ещё не сохранена, приложение не может показать собственный экран: действует ошибка браузера. Если оболочка доступна, но часть контента отсутствует, показывается собственная ошибка с повтором и выходом.

Браузер или пользователь может очистить локальные данные. Поэтому офлайн не обещается бессрочно: после удаления файлов требуется повторная загрузка. Установка на домашний экран сама по себе не заменяет проверку сохранённых ресурсов. [S9]

При недоступности service worker или хранилища онлайн-игра остаётся доступной, а офлайн-готовность не заявляется. `navigator.onLine` не использовать как единственный источник решения о доступности файлов.

### 12.4. Обновления

Код и контент публикуются как согласованная версия. Использовать ревизии/хеши файлов и версионирование кэша. `registerType: 'prompt'`; не перезагружать ребёнку игру при обнаружении новой версии. [S10]

Новый service worker ожидает естественной активации после закрытия всех окон старой версии. В родительском экране показывается наличие обновления и инструкция закрыть приложение и открыть заново. Принудительная активация через `skipWaiting` и перезагрузка текущей сессии в MVP не используются. Открытая вкладка старой версии может отсрочить активацию — инструкция должна это объяснять.

Сбой загрузки новой версии не удаляет рабочую старую. Устаревшие ресурсы очищаются при успешной активации, а не до окончания установки. Проверяется сценарий нескольких открытых вкладок.

## 13. GitHub Pages и изоляция

Публикуется только папка `dist`, без собственного API и серверного процесса. Используется GitHub Actions.

После успешных проверок push в `main` готовый артефакт автоматически публикуется отдельным workflow. Предусмотрен самостоятельный ручной «Деплой без тестов»: он выбирает последний либо явно указанный успешный запуск проверок `main` и повторно использует его неизменный артефакт. Тесты, Lighthouse и сборка в этом workflow не повторяются; обязательны сверка целостности и исходного коммита, изоляция от PR/сторонних веток и общая очередь публикаций. Отсутствующий или непроверенный артефакт не публикуется. После деплоя выполняется короткая HTTP-сверка идентификатора выпуска; расширенный браузерный smoke доступен отдельно.

Для адреса проекта `https://<user>.github.io/<repo>/` установить Vite `base: '/<repo>/'`. Для корневого домена базовый путь иной; его значение задаётся конфигурацией публикации, не строками в компонентах. Все пути картинок, звука, манифеста и service worker согласуются с этой базой. [S11]

Область service worker ограничена каталогом приложения. Манифест не ведёт в корень чужого проекта. Кэши и любые будущие ключи локального хранения имеют префикс `tamchy`.

**Нельзя очищать все кэши домена или отменять регистрацию всех service worker:** на том же пользовательском домене могут находиться другие приложения. Изоляция проверяется отдельным тестом.

Включить HTTPS. Не полагаться на доступ к настройке произвольных серверных маршрутов или HTTP-заголовков. Пользовательское поведение не должно зависеть от неизвестных будущих настроек GitHub Pages.

## 14. Производительность и совместимость

### 14.1. Бюджеты

Изображения имеют заранее известные размеры и не вызывают скачков. Загрузка следующих ресурсов не задерживает отклик. Не добавлять библиотеки анимации и предварительную оптимизацию сложных вычислений без измерений.

### 14.2. Матрица поддержки

Целевой минимум: Safari на iOS/iPadOS 17 и новее. Проверить минимальную заявленную и актуальную стабильную версии; неподтверждённую конфигурацию не отмечать протестированной. Настройки сборки должны соответствовать выбранному минимуму.

На Android — две последние стабильные версии Chrome на поддерживаемой ими ОС. На компьютере — две последние стабильные версии Chrome, Safari и Firefox для основного интерфейса. Установка PWA проверяется только там, где её предоставляет платформа.

Обязателен хотя бы один реальный iPhone и один реальный Android для звука, касаний и офлайн-запуска; планшетная компоновка проверяется дополнительно. Версии ОС и браузеров фиксируются в отчёте.

## 15. Конфиденциальность и безопасность

Не собирать имя, возраст, ответы, историю использования, идентификаторы ребёнка, геолокацию, голос и контакты. Не подключать аналитику, рекламу, удалённые журналы ошибок, внешние шрифты и сторонние скрипты. Приложение не запрашивает разрешения на камеру, микрофон, уведомления и геолокацию.

Сетевые запросы во время работы ограничены собственными статическими ресурсами и техническим обновлением. Все материалы считаются публичными. Секреты, ключи API и личные данные не добавлять в код, конфигурацию сборки и опубликованные файлы.

Текст выводить безопасным способом; не вставлять произвольный HTML. SVG проверять на скрипты и внешние ссылки. Зависимости проверять на известные уязвимости; существенные находки разбирать, а не игнорировать общей настройкой.

Краткая информация для взрослых должна описывать фактическую работу: приложение не хранит игровые результаты и не использует аналитику; локальные файлы нужны для офлайн. Не обещать полной анонимности: GitHub указывает, что IP-адреса посетителей Pages журналируются в целях безопасности. [S12]

Для иллюстраций, озвучки, значков и библиотек вести сведения о происхождении и условиях использования. Не копировать материалы аналогов. Этот раздел задаёт технические ограничения, но не является гарантией соответствия всем юрисдикциям; при изменении модели данных или монетизации требуется отдельная оценка.

## 16. TDD и автоматические проверки

### 16.1. Обязательный рабочий цикл

Для каждого поведения: сформулировать критерий → написать тест → запустить и убедиться, что он падает именно из-за отсутствующего поведения → реализовать минимум → получить успешный тест → улучшить структуру при сохранении зелёного набора.

Исправление ошибки начинается с теста, воспроизводящего её. Нельзя ослаблять ожидания, удалять проверки или массово обновлять эталоны только для получения успешной сборки. Начальная настройка инструментов и подготовка статических иллюстраций — допустимые исключения из буквального «сначала тест», но проверяются сборкой и проверочными сценариями.

### 16.2. Уровни

**Модульные:** генератор, правила циклов, проверка ответа, переходы, пауза, устаревшие события, валидация контента. Часы, источник случайности и внешние сервисы подменяемые. Для `domain/game` покрытие строк и ветвей не ниже 90%; обязательные сценарии важнее формального процента.

**Компонентные:** видимые состояния, доступные названия, домик, повтор, блокировка ответов, ошибки, число нарисованных предметов. Проверять действия и результат для пользователя, а не внутренние переменные, CSS-классы или порядок вызовов React. [S13]

**Интеграционные:** взаимодействие игры и аудиоадаптера, отмена запросов, события скрытия, переключение маршрутов, ошибки загрузки. Подменённый звук проверяет логику, но не доказывает реальное воспроизведение.

**Сквозные:** Playwright против итоговой сборки с настоящим service worker, а не только сервера разработки. Основные проекты — Chromium и WebKit с мобильными размерами; основные настольные сценарии дополнительно в Firefox. Не подменять кэш и сеть в тесте, который заявляет проверку настоящего офлайн. [S14]

WebKit в Playwright не равен установленному Safari на iPhone; реальная мобильная проверка остаётся обязательной. [S15]

После утверждения финальных материалов закрепить эталонные снимки главного экрана и трёх игр в мобильной и планшетной компоновке. Обновление визуальных эталонов проверяется вручную; оно не заменяет функциональные тесты.

### 16.3. Обязательные сценарии

| ID | Проверка |
|---|---|
| T01 | Главный экран → каждый из трёх разделов → домой |
| T02 | Правильный ответ: одна реакция, нужная озвучка, один следующий раунд |
| T03 | Неправильный ответ: тот же раунд и расположение, повтор задания |
| T04 | Две ошибки: подсказка, но без автоматического ответа |
| T05 | Повтор прерывает звук; запись не дублируется |
| T06 | Серия быстрых и одновременных касаний не нарушает состояние |
| T07 | Нет дубликатов вариантов; правильный вариант единственный; цели не повторяются подряд |
| T08 | Для каждого числа 1–5 количество яблок совпадает с данными |
| T09 | Домой/другой раздел отменяют прежние таймеры и звук |
| T10 | Сворачивание, блокировка и возврат не вызывают фонового ответа и наложения звука |
| T11 | Прямой адрес, обновление страницы, неизвестный маршрут и браузерный «Назад» |
| T12 | Неполная загрузка, ошибка картинки, MP3, декодирования и запрет аудио |
| T13 | Полная подготовка → отключение сети → новый запуск → все задания и все записи |
| T14 | Потеря сети во время первой подготовки не создаёт ложного статуса «готово» |
| T15 | Обновление A→B: старая игра не прерывается; сбой B не ломает A |
| T16 | Несколько вкладок и изоляция кэшей соседнего приложения |
| T17 | Проверяемые размеры окна, увеличение текста, уменьшенное движение, клавиатура |
| T18 | Нет внешних запросов, трекеров, отсутствующих ресурсов и ошибок консоли |

Не использовать реальные задержки в модульных тестах и произвольные ожидания времени в сквозных, когда можно ждать наблюдаемого состояния. Тесты изолированы; пустой кэш и подготовленный кэш — разные сценарии. Нестабильный тест исправляется, а не скрывается большим числом повторов. [S14]

## 17. Проверки перед публикацией

При подготовке нового выпуска запускать следующий набор. Повторная публикация готового проверенного артефакта по разделу 13 не повторяет эти команды. Для изменений только CI и документации достаточно проверок затронутых workflow, скриптов и ссылок без повторной приёмки неизменённого приложения:

```text
npm ci
npm run format:check
npm run lint
npm run typecheck
npm run validate:content
npm run test:unit -- --coverage
npm run test:integration
npm run build
npm run check:assets
npm run check:budgets
npm run test:e2e
```

Названия команд являются контрактом проекта; их реализации добавляются в `package.json`. Установка браузеров Playwright выполняется в подготовке CI.

Автоматическая подготовка графических производных по [руководству по контенту](content-guide.md) выполняется до `validate:content` и `build`, чтобы проверка путей и сборка использовали готовые WebP и иконки.

Публикация разрешена только после успеха проверок. Публикуется тот же артефакт `dist`, который прошёл тесты. Запросы изменений из сторонних веток не получают права публикации. Для задания публикации выдаются только необходимые права Pages; использовать официальные действия GitHub с зафиксированными версиями/ревизиями. [S11]

Настроить обязательные проверки основной ветки и исключить одновременную публикацию нескольких версий. После автоматической или повторной публикации выполнять HTTP-сверку идентификатора выпуска по реальному пути репозитория. Расширенную проверку приложения и обязательных ресурсов по опубликованному URL сохранять отдельной командой, не запускающейся в workflow «Деплой без тестов».

Процедура отката описывается в документации: повторная публикация последней рабочей версии и проверка поведения service worker. Откат на сервере не объявляется мгновенным обновлением уже открытого офлайн-приложения.

| ID | Критерий | Подтверждение |

| A07 | Установка и повторный запуск работают на целевых устройствах | Ручной протокол iPhone и Android |
| A08 | Обновления не прерывают игру и не повреждают соседние приложения | T15–T16 |

Для пользовательской проверки достаточно небольшого наблюдения с 2–3 представителями целевого возраста при согласии взрослых: проверяются основные действия и места затруднений, без записи личных данных и без утверждений о доказанной образовательной эффективности. Если такая проверка не проведена, критерий A02 остаётся непроверенным, а не автоматически выполненным.

В протоколе приёмки отдельно указывать: выполнено, не выполнено, не проверено. Разработка интерфейса на временных материалах допускается, публикация финального MVP с ними — нет.

## 19. Результат разработки и расширяемость

Передаются исходный код, зафиксированные зависимости, тесты, настроенные проверки и публикация, финальный комплект ресурсов, инструкция локального запуска, инструкция добавления контента, описание архитектуры, инструкция проверки офлайн/аудио/обновлений, список происхождения материалов и протокол приёмки.

Должны существовать команды `npm run dev` и `npm run preview`. Последняя предназначена для локальной проверки собранной версии, а не для собственного рабочего сервера. [S11]

Следующее развитие возможно после MVP: дополнительные элементы, новые темы, свободное знакомство, отдельная игра по голосам животных, диалоги, времена года и сказки. Не реализовывать их заранее и не создавать под них пустые экраны, конфигурационные платформы или плагины.

**Итоговая граница:** три раздела, одна механика, два варианта ответа, точные данные, собственная татарская озвучка, самостоятельная навигация, предсказуемый звук и проверенный офлайн. План работ и промты для реализации оформляются отдельно на основании этого ТЗ.
