# 5. Предметы для счёта

`count-apple.png` содержит строго одно яблоко. Количества, сравнение и арифметические задания строятся кодом, без готовых групп. Цифры — обычный текст.

Полный пул счётных объектов теперь включает **13 типов**: яблоко, шесть геометрических форм и шесть нейтральных предметов. Внутри одного задания используется один тип объекта с одинаковым размером, цветом и оформлением; правильность ответа не кодируется размером, тенью или детализацией. Нейтральные формы и предметы предварительно перекрашиваются той же формулой, что в цветовых механиках.

# 7. Геометрические формы — 6 PNG

| Форма         | Мастер                |
| ------------- | --------------------- |
| Круг          | `shape-circle.png`    |
| Квадрат       | `shape-square.png`    |
| Треугольник   | `shape-triangle.png`  |
| Прямоугольник | `shape-rectangle.png` |
| Овал          | `shape-oval.png`      |

Формат — PNG RGBA 1024×1024 с прозрачным фоном. У каждого пикселя с ненулевой альфой `R = G = B = 128`. По формуле раздела 9 основной цвет формы становится точным учебным HEX; альфа сохраняет её контур и сглаживание. Форма должна оставаться узнаваемой в небольшой карточке.

Размер задаётся при отображении, отдельные большие/маленькие мастера не создаются. Используется один нейтральный мастер для всех 13 цветов; `currentColor`, SVG-компоненты и SVG-маски для этих ресурсов больше не нужны.

# 8. Нейтральные предметы — 6 PNG

| Предмет            | Мастер                         |
| ------------------ | ------------------------------ |
| Мяч                | `color-object-ball.png`        |
| Игрушечное кольцо  | `color-object-ring-toy.png`    |
| Игрушечная машинка | `color-object-car-toy.png`     |
| Куб                | `color-object-cube.png`        |
| Пирамидка          | `color-object-pyramid-toy.png` |
| Юла                | `color-object-top.png`         |

Все предметы включены в C2 и пул счётных объектов. Прежнее исключение куба, пирамидки и юлы отменено. Для машинки используется PNG из нового архива.

Формат — PNG RGBA 1024×1024. В видимых пикселях `R = G = B`; текущие мастера имеют диапазон 48–224 и содержат базовый тон 128. Тон 128 обозначает основной учебный цвет, меньшие значения — тени, большие — блики. Швы, грани и объём сохраняются при перекраске. Нельзя заменять изображение однотонным силуэтом: это уничтожит предусмотренные детали.

Предметы узнаваемы, без текста, брендинга и фоновой сцены; основной цвет не должен вступать в противоречие с естественной окраской предмета. Дополнительные цвета в мастер не вводятся.

# 9. Программная перекраска PNG

Формула перенесена из README предоставленного архива. Для каждого RGB-канала `T` целевого учебного цвета и серого значения `M` PNG (целые 0…255):

```text
if M <= 128:
    C = T * M / 128
else:
    C = T + (255 - T) * (M - 128) / 127
```

Итоговый RGB-канал округляется до ближайшего целого в диапазоне 0…255. Альфа итогового пикселя берётся из нейтрального PNG без изменений. Расчёт выполняется по 8-битным RGB-значениям sRGB до умножения цвета на альфу; альфа не используется как яркость и не умножается на неё повторно. Цвет полностью прозрачных пикселей не участвует в учебном изображении.

Инварианты: `M = 0 → C = 0`, `M = 128 → C = T`, `M = 255 → C = 255`. У простых фигур все видимые пиксели имеют точный целевой RGB до композиции с фоном. У предметов точный HEX относится к базовому тону 128; тени и блики закономерно отличаются. Для белого и чёрного используется та же формула. Контраст с поверхностью обеспечивается общим оформлением, а не заменой учебного HEX.

Реализация использует `fast-png` в Web Worker для чтения точных серых значений и альфы, затем применяет формулу и передаёт готовые RGBA в Canvas 2D. Исходник не читается через `getImageData`: предварительная композиция Canvas могла бы изменить полупрозрачные RGB. Произвольные CSS-фильтры и заливка только по альфа-маске не заменяют этот контракт. Перекраска выполняется при подготовке ресурсов упражнения, вне React-рендера; ответы разрешаются после её готовности. Декодирование и результаты для текущих/ближайших комбинаций кэшируются с ограничением памяти. При выходе/смене упражнения устаревший результат игнорируется по идентификаторам операции.

13 цветных копий каждого мастера не хранятся в репозитории и не включаются в precache. В офлайн-набор входит нейтральный PNG и локальный код перекраски. Подготовка PNG и сервис перекраски реализованы. Подключение к упражнениям, полному офлайн-набору и приёмка на устройствах остаются в V2-07.

# 11. Что не создаётся отдельными файлами

- Цветовые фишки C1 формируются программно из точных HEX.
- Цвет, форма и размер C3 используют один нейтральный PNG и параметры отображения.
- Силуэты животных A3 формируются из альфа-канала существующих иллюстраций; дополнительные 39 файлов не нужны. Это отдельная механика, а не способ тонирования предметов.
- Цифры выводятся текстом, количества и состояния арифметики строятся кодом.
- JPG-превью и `master-stats.json` из архива — справочные материалы, они не являются учебными мастерами или ресурсами приложения.

# 12. Хранение и производные

Все мастер-PNG сохраняются побайтно, без пережатия, изменения размера и альфа-канала. Исходники из старого набора (44 PNG 1254×1254) не заменялись; добавлены 12 нейтральных PNG 1024×1024. Производные создаются отдельно.

Для категорий, животных и яблока сохраняется существующая схема WebP. Для нейтральных форм и предметов используются оптимизированные PNG без потерь, сохраняющие декодированные серые значения, размеры 1024×1024 и альфа-канал мастера. К ним нельзя применять существующее WebP-сжатие с потерями или квантование цвета: изменения значений `M` нарушат точный базовый тон. Для 12 нейтральных PNG владелец согласовал лимит 300 КиБ; для остальных иллюстраций сохраняется 150 КиБ. Производные кодируются как серый тон + альфа, без изменения восстановленных RGBA. Автоматическая проверка измерила 1 518 658 байт на весь нейтральный набор, крупнейший файл — 297 960 байт. На мастер-файлы лимит не распространяется.

# 13. Проверка ресурсов

Проверяются 56 уникальных ID и путей, SHA-256, декодирование всех PNG, размеры и альфа-канал. Дополнительно для 12 нейтральных мастеров: равенство RGB при ненулевой альфе, тон 128 у фигур, диапазон 48–224 и наличие базового тона у предметов. Подготовка автоматически сравнивает все декодированные RGBA с мастерами и проверяет бюджет. Модульные проверки покрывают 13 цветов, включая белый/чёрный, альфу и отмену операций. `check:tint` предназначен для проверки собранного worker и отображения в браузерах. Полный офлайн v2 и визуальная приёмка на устройствах ещё не выполнены.

Визуально необходимо проверить контуры, шум в полупрозрачных краях, сопоставимый масштаб и читаемость после окраски. Границы `alpha_bbox` из справочного JSON сами по себе не доказывают обрезание или его отсутствие. Техническая проверка не заменяет приёмку владельцем.

# 16. Происхождение и приёмка

Первые 44 PNG предоставлены владельцем ранее; нейтральные формы и предметы — в `tamchy-color-master-png-v1.zip`, вместе с описанием формулы и двумя превью. Все 12 новых мастеров сохранены без изменений. Прежние девять SVG удалены из активного дерева ресурсов. Дополнительные сведения об авторстве и условиях использования отдельно не предоставлены.

Пробная перекраска в приложении, финальная визуальная и языковая приёмка остаются открытыми. Признаки животных, конфликты силуэтов, компоновка и интеграция ресурсов отслеживаются в [разделе 21 ТЗ](specification.md#21-открытые-задачи-и-порядок-реализации).
