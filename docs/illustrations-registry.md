# 7. Геометрические формы — 6 SVG

Формы используются в старшем режиме раздела `Төсләр`, прежде всего в механике **«цвет + форма»**, а также могут переиспользоваться в цветовых закономерностях и других визуальных заданиях.

|   № | Форма         | Файл                  |
| --: | ------------- | --------------------- |
|   1 | Круг          | `shape-circle.svg`    |
|   2 | Квадрат       | `shape-square.svg`    |
|   3 | Треугольник   | `shape-triangle.svg`  |
|   4 | Прямоугольник | `shape-rectangle.svg` |
|   5 | Овал          | `shape-oval.svg`      |
|   6 | Звезда        | `shape-star.svg`      |

## Требования к формам

- чистый SVG;
- квадратный `viewBox="0 0 512 512"`;
- прозрачный фон;
- одна форма по центру;
- форма легко читается в маленьком размере;
- фигуры визуально различимы между собой;
- учебный цвет задаётся программно;
- основной цвет через `fill="currentColor"`;
- без текста;
- без встроенного растра;
- без внешних ссылок;
- без фильтров и тяжёлых эффектов;
- размер формы задаётся интерфейсом, отдельные SVG для «большой» и «маленькой» версии не создаются.

Отдельные файлы для каждой цветовой комбинации не создаются.

Например, не нужны:

```text
red-circle.svg
blue-circle.svg
big-red-circle.svg
small-green-square.svg
```

Один и тот же SVG используется с разными значениями цвета и масштаба.

# 8. Нейтральные цветовые предметы — 3 SVG

Используются в механике **«определи цвет предмета»**.

Итоговый утверждённый набор:

|   № | Предмет                    | Файл                        |
| --: | -------------------------- | --------------------------- |
|   1 | Мяч                        | `color-object-ball.svg`     |
|   2 | Игрушечное кольцо / бублик | `color-object-ring-toy.svg` |
|   3 | Игрушечная машинка         | `color-object-car-toy.svg`  |

Для машинки используется ранее утверждённый вариант, предшествующий последней переработке.

## Требования к предметам

- предмет должен быть легко узнаваемым;
- предмет должен быть нейтральным по отношению к учебному цвету;
- один SVG должен работать со всеми 13 учебными цветами;
- основной цвет задаётся программно через `currentColor`;
- допускаются дополнительные детали через тот же `currentColor` с прозрачностью;
- нельзя использовать второй фиксированный цвет, который меняет учебный смысл;
- прозрачный фон;
- без текста;
- без брендинга;
- без встроенного растра;
- без внешних ссылок;
- без сложных фильтров;
- предмет целиком помещается в `viewBox`;
- визуальная детализация не должна мешать определению основного цвета.

Предметы не должны иметь сильной естественной ассоциации с конкретным цветом. Поэтому для этой механики не используются, например, банан, снег или трава.

# 10. Учебная палитра для программного окрашивания

SVG-формы и SVG-предметы должны поддерживать все 13 утверждённых учебных цветов.

| ID           | Татарское название | HEX       |
| ------------ | ------------------ | --------- |
| `red`        | Кызыл              | `#D94343` |
| `orange`     | Кишер сары         | `#F28C28` |
| `yellow`     | Сары               | `#F3C63A` |
| `green`      | Яшел               | `#32965B` |
| `turquoise`  | Фирәзә             | `#2CAFA5` |
| `light-blue` | Күк зәңгәр         | `#4AA8E8` |
| `blue`       | Зәңгәр             | `#347FD4` |
| `purple`     | Шәмәхә             | `#7959C8` |
| `pink`       | Ал                 | `#E66D9A` |
| `brown`      | Көрән              | `#8A5A3B` |
| `gray`       | Соры               | `#7D8583` |
| `white`      | Ак                 | `#FFFFFF` |
| `black`      | Кара               | `#222625` |

Точный HEX является частью учебных данных и не должен изменяться ради визуального оформления.

Для белого `#FFFFFF`, если объект теряется на белой поверхности, контраст решается одинаковой для всех вариантов рамкой, подложкой или оформлением карточки. Сам учебный цвет не изменяется.

# 11. Что не требует отдельных иллюстраций

## 11.1. Цветовые фишки

Не создаются 13 отдельных PNG/WebP.

Цветовые варианты формируются программно из точных HEX-значений.

## 11.2. Цвет + форма

Не создаются отдельные растровые картинки каждой комбинации:

```text
цвет × форма × размер
```

Используются 6 базовых SVG-форм, а цвет и масштаб задаются кодом.

## 11.3. Силуэты животных

Не создаются дополнительные 39 изображений силуэтов.

Силуэт формируется локально из альфа-канала существующей иллюстрации животного.

Перед использованием механики необходимо вручную проверить все пары животных и зафиксировать конфликтующие силуэты, которые нельзя показывать одновременно.

## 11.4. Числа

Не создаются:

```text
number-1.png
number-2.png
...
number-20.png
```

Цифры отображаются программно как текст/интерфейс.

## 11.5. Количества

Не создаются отдельные картинки:

```text
2-apples.png
3-apples.png
...
20-apples.png
```

Группы строятся кодом из `count-apple.png`.

## 11.6. Визуальная арифметика

Не создаются готовые иллюстрации для каждого примера сложения или вычитания.

Группы предметов и состояние «убрано» формируются интерфейсом из базового счётного ресурса.

# 12. Общие требования к растровым учебным иллюстрациям

Для `categories`, `animals` и `count-apple`:

- единый утверждённый визуальный стиль «Тамчы»;
- квадратный холст;
- прозрачный фон;
- основной объект целиком, без обрезания;
- сопоставимый визуальный масштаб;
- минимум лишних деталей;
- без текста;
- без цифр;
- без интерфейсных элементов;
- без фоновой сцены;
- без посторонних предметов, если они не являются частью самого учебного объекта.

Мастер-исходники хранятся в PNG.

В приложение поставляются оптимизированные WebP.

# 13. Общие требования к SVG

Все 9 программных SVG:

```text
shape-circle.svg
shape-square.svg
shape-triangle.svg
shape-rectangle.svg
shape-oval.svg
shape-star.svg
color-object-ball.svg
color-object-ring-toy.svg
color-object-car-toy.svg
```

должны соответствовать следующим требованиям:

- валидный локальный SVG;
- `viewBox="0 0 512 512"`;
- прозрачный фон;
- без `<image>` и встроенного base64-растра;
- без сетевых ссылок;
- без JavaScript;
- без текста;
- основной цвет через `currentColor`;
- допускаются прозрачные слои того же `currentColor`;
- SVG должен корректно работать с любым из 13 учебных цветов;
- объект не должен выходить за границы `viewBox`;
- ресурс должен сохранять читаемость на мобильном экране.

При использовании `currentColor` SVG следует подключать способом, который позволяет передать CSS-свойство `color` внутрь SVG, например inline-SVG или через компонент. Обычный `<img src="...">` не передаёт `currentColor` из родительского элемента во внешний SVG.

# 16. Регистрация в проекте

Все 53 мастера находятся по путям раздела 2: 11 существующих PNG и дополнение из предоставленного владельцем `images.zip` (33 PNG животных + 9 SVG). Мастер-PNG имеют размер 1254×1254; 43 контентных изображения — RGBA, иконка — RGB. Исходные байты сохранены; `__MACOSX`, `.DS_Store` и служебные файлы архива не импортировались.

Машиночитаемый реестр — [`src/content/v2/graphics.json`](../src/content/v2/graphics.json): ID, исходник, планируемые пути производных и SHA-256. План поставки — 43 WebP, 9 SVG и четыре PNG-иконки. Производные v2 будут подключены на этапе V2-07; действующий MVP готовит только свои 10 WebP и четыре иконки.

SVG публикуются по путям `assets/images/shapes/` и `assets/images/color-objects/`; все URL разрешаются относительно Vite `base`. При многократном inline-подключении мяча и кольца локальные ID масок/градиентов должны быть уникальны в документе. Белый и чёрный внутри SVG-маски управляют прозрачностью и не являются дополнительными учебными цветами.

Происхождение: материалы предоставлены владельцем; отдельные сведения об авторстве и условиях использования не предоставлены. Состав и техническая проверка не заменяют визуальную приёмку. Признаки животных, конфликты силуэтов и компоновка отслеживаются в [открытых задачах ТЗ](specification.md#21-открытые-задачи-и-порядок-реализации).
